# Does the gain survive a strong start, and when does it pay? DINO-init adaptation, the time-to-payoff curve and a wider task panel `[engineering + new runs]` (P1.2.5)

*Design doc — a stand-in for the detail doc until the runs land. Bars fixed 2026-10-25, before any of this substudy's
data (revised the same day, before any data: DINO's own objective brought in scope; the supervised start, the enlarged
selection set, the `cls` readout and a forgetting reader for MAE-init JE folded in).*

**What this substudy is.** A P1.2 sub-study following [P1.2.4](P1.2.4.md) (see the [Phase 1 overview](index.md)). P1.2's
evidence for leg (a) so far rests on one start: the MAE-pretrained ViT-B, continued with a joint-embedding objective
("MAE-init JE"). That start is weak under linear probes, which flatters any adaptation. P1.2.5 asks the question the
project actually has to answer: **in a correlated driving stream, does continuously adapting the best available start
beat keeping that start frozen — and after how much of the stream?**

## Motivation

**The comparison that matters.** The project's setting is a temporally correlated stream; a deployment cannot opt out of
the correlation. So the main indicator is the correlated walk against the same start frozen, as in [P1.2.1](P1.2.1.md)'s
gate. The shuffled (IID) drive stays as an ablation.

**Why a strong start.** [P1.2.4](P1.2.4.md) found frozen DINO and a frozen supervised ViT-B ahead of the MAE start, most
of all on kNN (by 4–7 points), the read that matters for the selection filter. Adapted MAE-init JE beat frozen DINO on
scene only. A reviewer's first question is whether adaptation still pays when the start is already strong. DINO is a
label-free joint-embedding method, the same family as SimSiam. Its known failure mode, collapse, is what Phase 0's
joint-embedding signals and collapse control were built for, so adapting it stays inside the project's discipline. It is
not a replacement for the project's model classes; it is a better start for one of them.

**Why DINO's own objective, not only SimSiam.** P1.2's "JE" is a hybrid: MAE's weights under a SimSiam objective.
Continuing DINO with SimSiam would be another hybrid. Continuing DINO with DINO — the init's own objective, as MAE-init
MAE was — gives the clean, MAE-free joint-embedding result. SimSiam on DINO weights runs beside it: it needs no new
code, sits on the signals P1.1 validated, and separates "a better start" from "a different objective".

**Why a curve, not an end point.** "Is adaptation better?" depends on how much of the stream the model has seen.
P1.2.1's walk overtook the frozen start after roughly 10–15k frames and then plateaued on scene, while traffic light
kept climbing. A deployment needs that curve, and whether more of the same data keeps paying.

**Why more tasks.** Both of P1.2's tasks are narrow. The scene label has three classes and little headroom. The traffic
light is smaller than one 16-pixel patch at 224 px, so that task mostly reads intersection context. Larger objects and a
spatial (per-patch) read test what a driving deployment would use the features for.

**A loose end from P1.2.4.** Its attribution controls were matched to P1.2.1's recipe, not the confirmed protections
recipe whose gain it reports.

## Design

Common to every drive unless stated: BDD100K train, the three canary scenes, 224 px squash, batch 32, one pass, the
P1.2.1 reservations (`stream.well_fraction=0.05`, canary 100 + 100 per cell) with an **enlarged selection set** (below),
heads settled on the frozen encoder first (`warmup.freeze_encoder=true`), so step 0 *is* the frozen start. The full JE
health vector is logged every 25 steps. Reads are on BDD val (the P1.2.1 pool and split), on the readout ladder.

**The selection set, enlarged and labelled.** P1.2.4 found the 150 + 150-per-scene set too noisy to separate close arms
at one seed (a repeat of the same recipe read 0.018 apart). It grows to 450 + 450 per scene (2,700 frames) and is read
on every panel task (Part C), not the scene alone: the reader builds it as a full attributed pool. Its cost is ~1,800
fewer drive frames (about 56 steps), and new wells (see the prerequisites).

### Part A — The DINO-init gates (primary)

Two backbones from the same DINO ViT-B/16 start, each with its own gate, as P1.2.1 ran JE and MAE. Leg (a) at a strong
start passes if either passes. Their shared frozen floor, **B5-DINO**, is the downloaded DINO teacher backbone
(`encoder=vit_b16_dino`); each drive's step-0 encoder must be bit-identical to it (checked as in P1.2.1).

- **DINO-init DINO** (the init-matched objective). The full checkpoint resumed intact — student, teacher, both
    projection heads and the centre — so no heads need settling. The student trains; the teacher is the student's moving
    average (momentum 0.996 → 1 over the drive, DINO's schedule) and is the encoder read, as in DINO's own evaluation.
    Multi-crop at DINO's settings: 2 global crops at 224 (scale 0.4–1) and 6 local crops at 96 (scale 0.05–0.4); teacher
    temperature 0.04, student 0.1, centre momentum 0.9.
- **DINO-init SimSiam.** DINO's backbone with SimSiam heads settled on the frozen encoder, then the SimSiam drive, as
    MAE-init JE.

**A secondary start: supervised ViT-B + SimSiam.** The ImageNet-supervised ViT-B/16 (`encoder=vit_b16_pretrained`) is
the other strong floor. Its labels were spent before deployment, so label-free adaptation from it is fair game. Same
protocol as DINO-init SimSiam, against its own frozen floor. Gated and reported, not part of the claim table.

**The recipe, chosen without reading val.** Per backbone, P1.2.4's protections recipe (layer-wise lr decay 0.75, no
weight decay on norms, biases, position embeddings and tokens) at three learning rates — 1e-5, 3e-5, 9e-5 — one seed
each, on the walk. The arm with the best selection-set scene linear read at the end of the drive is chosen and recorded
here before its confirmation.

**The confirmation.** Per backbone, the chosen recipe on the walk × 5 fresh seeds, plus its IID control × 3 (secondary).
Checkpoints at the curve's steps (Part B).

**Readouts.** Every encoder is read on the mean-pooled patch embedding, as in P1.2.1; the gates use it. DINO and the
supervised ViT-B were trained on their `cls` token, so every frozen floor and adapted encoder is also read on `cls`,
secondary. If `cls` reverses a gate's direction, the claim says so.

**The resolution stays at 224 px.** It is the standard input for ViT-B/16 frozen-probe evaluation (the MAE and DINO
papers' linear probes). It is raised only if peer-reviewed studies of self-supervised features on driving data read the
same kind of probe at a higher resolution. That literature check is part of the engineering step, recorded here before
any run.

### Part B — The time-to-payoff curve

**Within one pass.** Every confirmation drive (Part A's, and a re-run of P1.2.4's confirmed MAE-init recipe, whose
drives saved only their end) saves checkpoints at 100 steps, at ⅛, ¼, ½ and ¾ of the drive, and at its end — about 3k,
7k, 14k, 27k, 41k and 54k frames. Each is read on val, frozen rungs (kNN, linear). In a single pass every frame is new,
so this is also the curve over unique frames.

**A second pass.** Three of each init's confirmation seeds continue for a second walk over the same frames (a fresh
optimizer from the pass-1 end state; `resume.checkpoint`, `resume.step=0`). Does repeating the data still pay, or has
the model absorbed what this split offers? New frames (BDD's driving videos) are the larger-horizon test; they belong to
P1.3 and are not run here.

**The caveat this cannot lift.** BDD val has the same distribution as BDD train. The curve measures adapting to a fixed
new domain, not to a stream that keeps shifting; that is P1.3's and Phase 4's question.

### Part C — The wider task panel

**Candidates.** Each is screened before any adapted encoder is read:

- `presence_cell:bus`, `presence_cell:truck`, `presence_cell:pedestrian` — presence, balanced within each scene ×
    time-of-day cell (as the traffic-light task).
- `large_cell:<vehicle>` — a car, bus or truck box covering at least 2% of the frame, cell-balanced: an object several
    patches wide.
- `weather` — clear / rainy / snowy (P1.2.0's runner-up, headroom +0.13).
- **Drivable area** — a per-patch linear probe on patch tokens: is each 16 × 16 patch mostly drivable? Read as
    patch-level balanced accuracy on held-out frames. The one spatial read in the panel.

**The screen** (P1.2.0's method, on the BDD *train* pool with frozen encoders only — no val, no adapted encoder): a task
is eligible if scene + time of day predict it at most 0.60 (overlap) and its headroom (full-label fine-tune ceiling
minus frozen linear) is at least +0.05 on **frozen DINO**, the stronger start. Every eligible task joins the panel, up
to four, in order of headroom. The panel is recorded here before any adapted encoder is read.

### Part D — Attribution under the confirmed MAE-init recipe

P1.2.4's two controls (COCO, Places365; 3 seeds each) and a BDD IID drive (3 seeds), all with P1.2.4's protections
recipe, from P1.2.1's settled-head JE well. Same matching, caches and contrast as P1.2.4. It answers P1.2.4's question
for the recipe it actually reports: can a one-off generic adaptation, then frozen, replace learning on the stream? For
DINO-init, the same controls run **only if a Part A gate passes**, on the passing backbone.

**A secondary read from the same drives: the forgetting lead under the confirmed recipes.** P1.2.1's lead was the walk
costing JE's kNN at night against the IID control. The protections recipe removed the loss against B5, but the
walk-vs-IID contrast was never re-run with it. Part B's MAE-init walk and Part D's BDD IID drive share that recipe, and
Part A has both orders at DINO init, so P1.2.1's secondary reads (walk vs IID, by time of day) are re-run for both
inits, descriptively.

### Part E — Health signals: transfer to DINO, and a reader for MAE-init JE's forgetting

**Transfer to a DINO start.** The JE signals were re-checked on MAE-init JE in [P1.1](../latest-results/P1.1.md).
DINO-init drives are healthy unless the gate says otherwise, so they are a transfer test: read each DINO-init walk
against P1.1.0's healthy bands with [P1.1.1](P1.1.1.md)'s single-drive rule, and report the false-alarm rate per panel.
A rate near P1.1's (~1 in 10) means the bands transfer; much higher means a DINO start needs its own null before P1.3 or
P1.4 use it.

**A collapse control for DINO's objective** — Phase 0's discipline for any new JE method. Two short drives from the DINO
checkpoint, each with one of DINO's two documented collapse switches thrown: centring off (one dimension dominates) and
sharpening off (a uniform output). The JE signals (projector and backbone rank, spread) must fire on both, and the
labelled canary must confirm the damage, before any DINO-objective drive is read as healthy.

**A label-free reader for MAE-init JE losing its MAE-pretrained information.** [P1.2.4](P1.2.4.md) found none: MAE's
mid-block CKA drift ([P1.1.3](P1.1.3.md)) was validated on MAE-objective runs only, and backbone CKA drift is nearly
blind to damage on the hybrid ([P1.1.2](P1.1.2.md)). So P1.1.3's read is repeated for MAE-init JE: per-block CKA drift
against the settled-head well, on P1.1.1's JE damage branches (positives) and Part B's healthy MAE-init walks
(negatives). Reported as P1.1.2's screen reports it: damage caught, healthy walks quiet.

### Pass bars (fixed before any of this substudy's data)

Seed × image bootstrap intervals throughout, as P1.2.1; one-sided tests at family-wise 0.05 with Holm.

**A — the DINO-init gates.** Per backbone (DINO-init DINO and DINO-init SimSiam; the supervised start reported),
P1.2.1's bars as written, with the start's frozen encoder as the floor: primary rung linear on the mean-pooled readout,
gate tasks scene and cell-balanced traffic light.

- **PASS** — on at least one gate task, Δ (adapted − B5-DINO) has one-sided p ≤ 0.025 (Holm over two).
- **FAIL** — on both gate tasks, every rung's upper bound is below +0.02.
- **INCONCLUSIVE** — anything else (then five more seeds, read once at 10).

**C — breadth (secondary, reported for both inits).** On each panel task, Δ on the linear rung against the init's own
frozen floor, Holm over the panel. Reported as "gains on *k* of *n* tasks", with the kNN rung beside it. No verdict
hangs on it alone; it qualifies the claim below.

**B — the curve (descriptive, two reads fixed in advance).**

- **Time to payoff** — the first checkpoint whose linear Δ against the frozen floor has its lower bound above zero, per
    task and init.
- **Still rising** — the second pass's end against the first pass's end (paired by seed, two-sample bootstrap):
    one-sided p ≤ 0.05 for a gain.

**D — attribution.** P1.2.4's bars as written, per control; the claim is the weaker of the two.

**E — signals.** Descriptive: the false-alarm rate per panel against P1.1's; the collapse control fires (both switches,
signals and canary), or the DINO-objective arm is not read; the MAE-init JE reader's catch rate and healthy-walk quiet
rate, as P1.1.2 reports them.

**The claim P1.2 can make after P1.2.5:**

| DINO-init gate (either backbone) | Breadth (the passing backbone) | Claim |
| -- | -- | -- |
| PASS | gains on most panel tasks | **Strong** — adapting the best start tried beats keeping it frozen, broadly |
| PASS | gains on few | **Qualified** — adaptation beats a strong frozen start, on some tasks |
| INCONCLUSIVE / FAIL | — | **Weak** for strong starts — adaptation pays for weak starts (MAE-init) only; raised with the user before P1.3, with the scale caveat (one pass, a fixed domain) |

"Most" means more than half of the panel. If both DINO-init backbones pass, the claim uses the broader one.

### Engineering

- **The prerequisites above**, labels first (they decide whether two Part C candidates survive).
- **DINO's objective** as an SSL method (`cafl4ds/ssl/dino.py`, `backbone=dino`): student and moving-average teacher,
    multi-crop, centring and sharpening, resumed from the full checkpoint; the two collapse switches; the monitor's JE
    family.
- **The selection set as an attributed pool** (`pool.kind=selection` reading every task), and the 450 + 450 reservation.
- **New task labels** in `cafl4ds/adaptation.py`: `large_cell:<categories>:<min_area>` from box areas; the drivable-area
    per-patch target (rasterized polygons pooled to the patch grid) and its patch-token probe in the reader.
- **A `cls` readout** option in the reader for every encoder.
- **Checkpoint steps** at the curve's fractions (`checkpoint_legs=steps`, exists); the second pass via
    `resume.checkpoint` with `resume.step=0` (exists; check that it replays the full walk).
- **Off-domain subsets**: a seed-fixed `n_images` subset of an existing cache (Part D's re-matching).
- **The signal reads** (Part E): P1.1.1's rule on a new corpus against P1.1.0's bands; P1.1.3's per-block drift on JE.
- **The breadth and curve reads** in `scripts/analyze_adaptation.py` (`mode=p125`).
- **The resolution check** (Part A) against the literature, recorded here.
- Tests on the synthetic source for each; pre-commit clean.
