# Healthy-movement null + canary probe power `[engineering + new runs]` (P1.1.0)

**What this substudy is.** The first P1.1 sub-study (see the [Phase 1 overview](index.md)). Phase 1 asks whether a
self-supervised backbone, trained on a correlated stream of driving images, *degrades*. We watch it through a set of
health instruments. The catch, which Phase 0 established, is that a perfectly healthy backbone *also* moves those
instruments while it trains ([P0.1.0](../phase0/P0.1.0.md), [P0.2.1](../phase0/P0.2.1.md)). So a reading from the
correlated stream means nothing until we know how much a healthy run moves them. That reference is the **null**, and
this sub-study measures it. It also checks whether our labelled accuracy channel (the **canary**) is precise enough to
serve as ground truth, and whether the null depends on how **familiar** the stream's frames are to the starting model.

**Verdict.** **All three questions are answered.** From a well-settled backbone, a healthy drive is quiet. On top of
that, correlation alone reshapes the joint-embedding (JE) backbone's representation without costing it any accuracy, and
leaves the MAE backbone essentially untouched. The canary is precise enough to have caught a loss of a few points, and
it saw none. Familiarity has no large effect.

| Question | Answer | How firm |
| -- | -- | -- |
| **1. How much does a healthy drive move the instruments, and does the correlated drive move them beyond that?** | From a settled well, the healthy drive barely moves anything (JE's projector RankMe 10.38 → 10.38). Beyond that: on **JE**, correlation compresses the projector (its RankMe falls up to 1.66–1.75× below the healthy drive's) and pulls the representation ~4–10× further from the well — with no accuracy cost. On **MAE**, correlation leaves no meaningful trace. | Firm: 5 seeds per arm, an exact permutation test, the same picture at both familiarity levels. |
| **2. Is the canary strong enough to be ground truth?** | Yes. It resolves a loss of ~2–4.5 points pooled (~4–7.5 per time-of-day stratum), and the wells now sit 0.11–0.30 above chance, so a loss has room to show. | Firm. |
| **3. Does familiarity shift the null?** | No detectable effect: the drive behaves the same whether or not the well already saw its frames. | Partial. One well per level, so only a large effect is ruled out; the test on genuinely new frames is P1.3's. |

Three things follow. First, a null is only meaningful from a **settled** starting point: the large "healthy movement"
our first, shallow attempt recorded was mostly the starting model still settling. Second, exactly **one phenomenon**
needs explaining — JE's correlation-driven compression and drift with flat accuracy — and calling it harmful collapse or
harmless reorganization is [P1.1.1](index.md)'s first job. Its size sits below Phase 0's alarm bar. Third, this is
**not** evidence that streaming is harmless in general: the drive is short (119 steps, about one pass over ~3,500
frames). Damage over a long horizon is P1.3's question.

## The setup in plain terms

- **The drive.** A backbone trains on a stream of BDD100K driving frames, batch by batch, once. The stream is the
    **walk**: it visits one driving condition at a time (e.g. day·clear, then dusk, then night), so consecutive batches
    are highly correlated. Each condition is a **leg**.
- **The healthy control (IID).** The *same* frames, in the same batch sizes and number of steps, but shuffled across
    conditions. It differs from the walk only in ordering, so any gap between the two comes from correlation alone.
- **The well.** The model the drive starts from — trained beforehand on a separate pool of frames until it is competent.
    Every drive in a comparison starts from the identical well.
- **Two backbones.** **JE** (joint-embedding, here SimSiam) learns by making two augmented views of an image agree;
    **MAE** (masked autoencoder) learns by reconstructing hidden image patches. Phase 0 found they fail differently: JE
    can collapse, MAE tends to resist forgetting.
- **The instruments.**
    - *RankMe* — how many dimensions the representation effectively uses. A fall means the representation is getting
        compressed; a large fall is the signature of collapse. On JE it is read both on the backbone and on the
        **projector** (the small head SimSiam trains through, where Phase 0 calibrated its collapse readers).
    - *Drift* (`cka_drift`, `cosine_drift`) — how far the representation of a fixed image set has moved away from the
        well's.
    - *The canary* — labelled accuracy on a fixed probe set: predict the scene (city street / highway / residential) from
        frozen features, with a nearest-neighbour (**kNN**) and a **linear** classifier. Chance is 0.33. It is the one
        channel that directly measures quality.
- **Familiarity (`well_overlap`).** The share of the drive's frames the well already trained on: 0 = all new, 1 = all
    seen before.

## Why — the three questions

Leg (b) of the Phase-1 exit gate asks whether streaming induces *measurable degradation*. "The needle moved" is not
evidence, because every needle moves under any training. A reading counts only if it moves *more than a healthy drive's
does*. That is question 1.

Two more questions ride along, because P1.1.1 (the reading protocol) and P1.3 (forgetting) both lean on the answers:

- **Question 2 — is the canary strong enough to be ground truth?** The prototype harness (P1.0.2) left it thin: 75 query
    images and a mean only a few points over chance. If it cannot resolve a realistic gap, it cannot arbitrate
    "degradation vs. benign" either.
- **Question 3 — does familiarity shift the null?** If the well already saw the drive's frames, the drive replays known
    images, which plausibly moves the model less. P1.3 will drive on BDD *train*, where every frame is new. A null
    measured on familiar frames could therefore be too narrow, and make benign movement there look like degradation.

## Methodology

### The matched healthy control

`RegimeStream(order="iid")` delivers the **exact images** the walk delivers, at the walk's **per-step batch sizes** and
**step count**, shuffled across regimes. The shuffle draws from the drive seed's private generator *after* the walk is
built, so it cannot perturb the walk itself. Every comparison is made checkpoint-for-checkpoint on the shared step grid,
and the analysis refuses a pair whose steps differ.

### A settled, competent well

A null measured from a weak or unsettled well is not worth much, and the first attempt showed why (see
[the shallow sweep](#the-first-attempt-shallow-wells-and-the-five-level-familiarity-sweep)). A good well needs two
properties.

- **It must be competent**, so the canary has room to fall. A well near chance cannot show a loss.
- **It must be settled.** Continued training first *pulls a pretrained model's quality down* — new training heads, a new
    learning rate and a new loss take time to bed in — before it levels off (the [P0.3.9](../phase0/P0.3.9.md) /
    [P0.3.10](../phase0/P0.3.10.md) lesson). A drive started mid-slide inherits the rest of the slide, and it would read
    as degradation.

**Getting a competent backbone took a detour.** The first wells were the project's from-scratch tiny ViT (4 layers, 64
px). A competence study scored every candidate the same tight way: probes fit on a class-balanced subsample of the
well's training pool (500 per scene), and scored by **balanced accuracy** (the mean of the per-class accuracies, so the
majority city-street class cannot inflate it) on ~3,800 drive frames no encoder trains on.

| Encoder | Training | kNN | Linear (or trained head) |
| -- | -- | -- | -- |
| Tiny ViT, random init | none | 0.41–0.43 | 0.46 |
| Tiny ViT, SSL wells | ~100–20,000 steps, 64–128 px, up to 61k frames | JE 0.42–0.45 · MAE 0.42–0.50 | JE 0.47–0.48 · MAE 0.47–0.54 |
| Tiny ViT, supervised | labels, 30 epochs (also: other lr, 128 px, CPU, 30k labelled frames) | — | head 0.50–0.53 |
| ViT-B/16 ImageNet-supervised, frozen | none (64 / 224 px) | 0.61 / 0.64 | 0.56 / 0.62 |
| ViT-B/16 MAE, frozen | none (64 / 224 px) | 0.52 / 0.53 | 0.58 / 0.63 |
| ViT-B/16, fine-tuned with labels | labels, 224 px (ImageNet / MAE init) | — | head 0.75 / 0.74 |

The frames carry the signal: a labelled ViT-B reaches ~0.74, the practical ceiling for these noisy scene labels. The
tiny ViT is the bottleneck. Even trained *with labels* it tops out at ~0.50–0.53 and cannot fit its own training set,
and no amount of extra data, resolution or learning-rate tuning changes that. Its SSL wells sit at the random-weights
level. So the deep wells use a **pretrained ViT-B/16 at 224 px**.

**Warming it to a plateau.** A scout warmed ViT-B for 3,000 steps per setting and logged competence every 100 steps
(drive-pool balanced accuracy, kNN / linear):

| Backbone · starting weights | Best lr | Start | Settled (steps 2,000–3,000) |
| -- | -- | -- | -- |
| JE · ImageNet-supervised | 3e-5 | 0.64 / 0.62 | 0.57 / 0.65 |
| JE · MAE | 3e-5 | 0.53 / 0.63 | 0.55 / 0.64 |
| MAE · MAE | 1e-4 | 0.53 / 0.63 | 0.53 / 0.55 |

Every run dips in its first 100–500 steps and levels off by ~1,500–2,000 — the expected settling. JE's linear read
recovers to slightly above its start. MAE's settles ~0.07 below, while its loss keeps falling (Phase 0's "the loss lies"
again, [P0.5](../latest-results/P0.5.md)). The other learning rates (1e-5 and 1e-4 for JE; 1e-5 and 3e-5 for MAE) dip
deeper or settle lower.

**The recipe.** Both backbones start from the **MAE weights** (`encoder=vit_b16_mae`). That keeps the pipeline
label-free end to end and gives both one shared start, at a JE plateau within 0.03 of the ImageNet start's. JE trains at
lr 3e-5 and MAE at 1e-4, in the well and in the drive. The well stops on **competence, not loss**:

- *What it reads.* A **selection set** — a third labelled reservation per scene, disjoint from the canary's probes, the
    well's pool and the drive — read every 100 steps. The well must never be stopped on the canary itself: that would
    select on the canary's noise, and the drive's regression to the mean would then look like degradation.
- *Its size.* **150 + 150 images per scene.** The scout showed a 50 + 50 set jitters 0.025–0.035 from reading to reading
    on the plateau, against ~0.01 for the 3,800-frame read, and barely tracks it (r ≈ 0–0.4).
- *The rule.* Stop when the selection kNN accuracy, averaged over the last 1,000 steps, differs from the 1,000 before by
    less than 0.015 **in either direction** (after at least 2,000 steps; at most 6,000). Two-sided, because several
    scout runs kept *sliding* slowly after the dip, and a rule that only waits for gains to stop would fire mid-slide.

### Instrument fixes

- **A larger, stratified probe set.** Every instrument reads the same fixed probe images, so P1.0.2's 75 query images
    capped RankMe at 75 and starved the canary. Probes are now reserved per **(time of day × scene)** cell — 45 support
    and 45 query images in each of 9 cells — giving 405 query images pooled and 135 per stratum. The smallest val cell
    (dawn/dusk × residential, 96 frames) sets that ceiling.
- **A per-stratum canary.** Beside the pooled accuracy, the monitor scores the query images of each time of day
    separately (`knn_acc_<stratum>` / `linear_acc_<stratum>`, for `daytime`, `dawn_dusk`, `night`). This is the channel
    a forgetting read needs — "did daytime accuracy fall while the walk sat at night?" — which the pooled canary cannot
    see.
- **Drift anchored to the frozen well** (`anchor=`, defaulting to the well), not to the run's own first checkpoint —
    Phase 0's "fixed, independent reference" principle.
- **Grad norm in the corpus** — the largest gradient norm since the previous checkpoint.
- **Leg-boundary checkpoints** (`checkpoint_legs=true`) — the full model saved at the start of every leg and at the end,
    so costly reads (P1.1.1's recovery test, P1.3's fine-tune probe) can run afterwards. The IID control saves at the
    same steps.

### The well/drive split and the familiarity knob

`stream.well_fraction=0.5` reserves a fixed half of each regime's training frames for the well; the drive never streams
them. `stream.well_overlap` then dials familiarity back in **without moving anything else**: the well pool keeps its
size, but that fraction of it is swapped for frames the drive also streams. The drive itself — images, order, batching —
is bit-identical at every level. Sweeping `well_fraction` instead was rejected: it is effectively on/off for
familiarity, while what it does vary (drive length, well data size) would confound the read.

### Statistics

Every comparison is walk vs. IID on the matched checkpoint grid, 5 seeds per arm.

- **Effect size.** Per checkpoint, *d* = (walk mean − IID mean) / pooled seed SD.
- **Significance.** An exact **seed-label permutation test**: all 252 ways to split the 10 seeds into two groups of 5,
    recomputing the max-over-checkpoints |*d*| in each. Taking the maximum *inside* each split controls false alarms
    across the ~120 correlated checkpoints. The smallest attainable p is 2/252 ≈ 0.008. `frac_sig` is the share of
    checkpoints individually significant under that control.
- **Canary power.** The minimum detectable walk-vs-IID gap (MDD; two-sided 5%, 80% power) is
    `(t₀.₉₇₅ + t₀.₈₀; df = 8) · sd_seed · √(2/5)`, with `sd_seed` the across-seed spread. Because every arm reads the
    *same* probe images, the probes' own sampling error is shared and cancels in the contrast; the seed spread is what
    limits it. The Wilson 95% interval on a single reading (±0.05 pooled) matters only for generalizing a reading to all
    of BDD.

An independent code review replaced a first draft of these statistics (a raw "z" against 1.96, an envelope-exceedance
fraction, a normal-quantile MDD) before analysis; the permutation test is unit-tested to hold its level on
autocorrelated null trajectories.

### The runs

All on BDD100K **val** (8,753 images after dropping rare scenes), batch 32, AdamW, on two Gaudi2 cards.

- **Deep wells (the primary null).** ViT-B/16, 224 px, the recipe above. {JE, MAE} × overlap {0, 1} × {walk, IID} × 5
    seeds — 4 wells, 40 drive seeds. A **119-step drive over 18 legs** (3,522 frames; the well pool keeps 3,521).
    Overlap 0 saves leg checkpoints. The wells took ~15–20 min each, a drive seed ~26 min (~9 h in all). All 40 seed
    reports pass both P1.0.2 validation tiers.
- **Shallow wells (the first attempt, and the five-level familiarity sweep).** The tiny ViT at 64 px, wells stopped on
    the SSL loss plateau. {JE, MAE} × overlap {0, 0.25, 0.5, 0.75, 1} × {walk, IID} × 5 seeds, plus a cold (from
    scratch) JE pair × 3 seeds. A 133-step drive over 18 legs. All 106 seed reports pass both tiers (2.5 h).

## Results

### The deep wells are competent and settled

Each well stopped on its competence plateau after 2,000–2,500 steps (~18–23 passes over the well pool). On the canary's
probes:

| Well | kNN | Linear |
| -- | -- | -- |
| JE, overlap 0 / 1 | 0.53 / 0.53 | 0.63 / 0.60 |
| MAE, overlap 0 / 1 | 0.50 / 0.44 | 0.54 / 0.55 |

That is 0.11–0.30 above chance and 0.11–0.30 below the ~0.74 fine-tuned ceiling, so the canary can move either way. The
shallow wells read 0.35–0.45.

### Question 1 — the null, and what correlation adds on top

**The healthy drive is now nearly still.** Under IID, the deep JE well's projector RankMe ends exactly where it started
(10.38 → 10.38); the shallow well's fell by a quarter (5.4 → 4.0). Drift from the well stays small (`cka_drift` ≤ 0.014
for JE, ≤ 0.03 for MAE). So most of the shallow null's "benign movement" was the well still settling. The movement Phase
0 warned about is real, but it is largely a property of an unsettled start.

**JE: correlation compresses the projector and moves the representation — the canary stays flat.**

| Overlap | Projector RankMe, IID / walk (end) | Peak IID / walk ratio | `cka_drift`, IID / walk (end) | Canary gap walk − IID, kNN / linear (p) |
| -- | -- | -- | -- | -- |
| 0 | 10.38 / 8.30 | 1.66× | 0.012 / 0.127 | +0.003 / +0.029 (0.87 / 0.16) |
| 1 | 9.89 / 8.59 | 1.75× | 0.033 / 0.132 | +0.010 / +0.001 (0.42 / 0.96) |

- **Compression.** The projector readers separate walk from IID at both levels (projector RankMe p ≤ 0.016, projector
    uniformity p = 0.008, final *d* +3.2 to +4.9). At overlap 0 the backbone's own RankMe separates too (p = 0.008,
    significant at 31% of checkpoints).
- **Drift.** The walk ends ~4–10× further from the well than IID, on both drift readers (p = 0.008 at both levels,
    significant at 46–74% of checkpoints).
- **Below Phase 0's bar.** Phase 0 calibrated a 2.0× RankMe ratio as its collapse alarm. The peak here is 1.66–1.75×.
- **No accuracy cost.** Walk-vs-IID canary gaps are within ±0.03 and never significant. Where they differ, the walk is
    *ahead*. The walk's own canary does not fall below its start either (linear 0.629 → 0.618, against an MDD of 0.038).

**MAE: correlation leaves essentially no trace.** Backbone RankMe does not separate (p = 0.08 / 0.18). The drift readers
clear p ≤ 0.04 at overlap 0, but the gaps are tiny (≤ 0.004 at the end), and the canary gaps are ≤ 0.003. Phase 0 showed
MAE's geometry is not a quality reader ([P0.5](../latest-results/P0.5.md)), but here even the geometry is quiet. **MAE
resists** the correlated drive at this horizon.

### Question 2 — the canary's power

The seed spread is small, so a paired walk-vs-IID contrast resolves a few points:

| Read | Mean | Seed SD | MDD (5 vs 5 seeds) |
| -- | -- | -- | -- |
| Pooled, JE (kNN / linear) | 0.52–0.53 / 0.60–0.61 | 0.012–0.022 | 0.024–0.045 |
| Pooled, MAE (kNN / linear) | 0.47 / 0.55–0.56 | 0.011–0.016 | 0.021–0.032 |
| Per time-of-day stratum (both) | — | — | 0.036–0.075 |

So "no canary loss" means "no loss larger than ~2–4.5 points pooled". On the shallow wells the precision was similar
(MDD 0.025–0.039 pooled), but the wells sat a few points above chance, so the canary had nothing to lose. The deep wells
fix that: the limit is now precision, not headroom.

**No forgetting signature.** A forgetting backbone would lose daytime accuracy while the walk sits in the night legs. A
handful of single strata clear p < 0.05 (JE daytime kNN at overlap 0, JE night kNN at overlap 1, MAE daytime kNN at
overlap 0). In every one the walk is *ahead* by 0.02–0.03, and none recurs across levels.

### Question 3 — familiarity

Overlap 0 and 1 tell the same story on the deep wells: JE's compression and drift at both levels, MAE quiet at both. The
shallow sweep covered five levels and found no trend either: no signal's IID movement trends across them (Spearman over
levels, all p ≥ 0.23), and JE's projector effect appears at every level. The limit is that there is **one well per
level**, so a level cannot be separated from its well draw. Only a large familiarity effect is ruled out.

### The first attempt: shallow wells, and the five-level familiarity sweep

The first wells stopped on the SSL **loss** plateau after 98–140 steps — under one pass over the well pool — at a canary
of kNN 0.35–0.42 / linear 0.42–0.45. The competence study later showed these wells score at the level of a *randomly
initialized* encoder. Their results, and what survived at depth:

| Shallow-well finding | At depth |
| -- | -- |
| The healthy null moves a lot (JE projector RankMe 5.4–6.2 → 3.5–4.0; drift climbs) | **Did not survive** — the well was settling |
| JE: the walk pushes the projector readers past Phase 0's bar (peak IID/walk RankMe 1.95–2.43×, p ≤ 0.016 at every level); strongest on the night legs; canary flat | **Survived, smaller** (1.66–1.75×), now with drift separating too |
| MAE: the walk lowers backbone RankMe and raises drift (walk `cka_drift` 0.38 vs IID 0.06 at overlap 0); canary flat | **Did not survive** — walk ≈ IID at depth |
| Loss and grad norm separate walk from IID (p ≤ 0.016) | **Survived** — and it is mechanical: walk batches come from one regime, IID batches mix all of them, so this is a property of the diet, not a health signal |
| No familiarity effect across five levels | **Survived** at two levels |

Two smaller shallow-sweep notes remain useful. A healthy AdamW run can spike its grad norm: one IID drive logged 290
against a median of 0.11, with no divergence — a caution if grad norm is ever used as an alarm on this recipe (cf.
[P0.4](../latest-results/P0.4.md)). And the cold (from-scratch) JE pair points the same way as warm JE, but with 3 + 3
seeds its p cannot fall below 0.10, so it stays descriptive.

### Reading caveats

All of these are shared by both arms, so they cancel in the walk-vs-IID contrast. They matter for anyone reading
*absolute* movement.

- **The last checkpoint follows a 3-image batch.** The walk's last leg ends on 3 frames, and the IID control copies the
    walk's batch sizes. A 3-image loss and grad norm are noise: the JE IID loss sits flat at −0.97 for 118 steps and
    reads −0.63 at the last one, with grad norm jumping from ~0.3 to ~9. Read loss and grad norm from max |*d*| and
    `frac_sig`, not their endpoints. The shallow sweep's loss and grad-norm conclusions rest on those, so they stand.
- **The drive restarts the optimizer.** A well stores the model, not AdamW's running estimates, so each drive begins
    with a fresh optimizer. MAE's grad norm jumps 1.1 → 8.1 on the first step and settles within ~5 steps. The JE canary
    dips ~0.02 in the first 10 steps.
- **The deep overlap-1 wells' drive-pool traces are invalid.** At overlap 1 the well pool *is* the drive pool, so that
    diagnostic read scored frames it had been fitted on (0.85). It is now fitted only on drive-disjoint frames and
    switches off at overlap 1. It never fed a stop or a result.

## Insights

- **A null is only as good as its starting point.** The same measurement from an unsettled well recorded large "healthy
    movement" that was really the well still settling. From a well warmed to its competence plateau, the healthy drive
    is quiet. Any future null — P1.3's long horizon included — must start from a settled, competent well.
- **Warm to competence, not to loss.** The SSL loss stopped the shallow wells within one pass, at random-encoder
    quality. A pretrained backbone first *loses* competence under continued SSL and then levels off; the stop has to
    watch that, on labels the canary never sees, and in both directions.
- **Correlation acts on JE's geometry, not (yet) its quality.** The walk compresses JE's projector and moves its
    representation, while a canary able to see a ~3-point loss stays flat. That is the precise question P1.1.1 inherits:
    early collapse the 3-class canary cannot see, or harmless compression.
- **MAE resists, again.** The correlated drive leaves no trace on MAE beyond noise, which extends the Phase-0 refrain to
    the deployment diet at this horizon. The shallow sweep's MAE "effects" were an unsettled-well artifact.
- **The model mattered more than the data.** Up to ~15× more data, higher resolution and longer training did not lift
    the tiny ViT; with labels it still could not learn the task. A pretrained ViT-B fixed it at once.

## What P1.1.1 inherits

- **The target:** JE's correlation-driven projector compression (peak 1.66–1.75×) and drift (~4–10×) with a flat canary.
    The tools: the mean-reversion and recovery tests (a short IID pass after the drive, from the overlap-0 leg
    checkpoints), and the surgical dose-controlled positive control, to call it collapse or benign compression.
- **The null:** per-instrument IID movement and seed spread, for both backbones, in
    [`deep/null_report.json`](artifacts/P1.1.0/deep/null_report.json).
- **The wells and the recipe:** `wells/p110_deep/` (gitignored; regenerable below).
- **Two reading rules:** read loss and grad norm from max |*d*|, not the last checkpoint; and when reading absolute
    movement, either save AdamW's state with the well or skip the drive's first ~10 steps.

## Code validity

An independent review of the P1.1.0 code (scratch checks on the synthetic source) verified that: the IID control matches
the walk exactly across batch sizes, `drop_last` and `block_size`; probes are balanced and disjoint from drive and well
at every overlap level and drive seed; the drive is identical across overlap levels; leg checkpoints capture the state
after exactly *s* completed batches; anchoring and the per-stratum masks are correct; and the grad-norm windowing is
right. Its statistical findings were fixed before analysis (see [Statistics](#statistics)).

Its latent harness findings were fixed before the deep runs, none changing a shallow-sweep number:

- Leg checkpoints index `batches_seen`, write `index.json` even on an early stop, and refuse a second pass.
- The drift anchor is read on the run's device. This was the one fix that could have touched a number: the shallow sweep
    read its anchor on CPU while driving on HPU. Re-reading the wells' probe embeddings on both devices puts that floor
    at ≤ 1.2e-7 in `cka_drift` and 0 in `cosine_drift`, so the shallow drift numbers stand.
- Each report header records the realized `familiarity` and `n_probe_query`; `analyze_null.py` reads the latter from the
    run.
- `warm_well.py` writes `<well>.split.json` (a fingerprint of the probe and well reservations), and the drive refuses a
    well reserved differently.
- The monitor warns when an anchor lacks a surface the run tracks; `with_grad_norm` is linear-time; the study label is
    the `study` config key (pass `study=P1.1.0`).

## How to run

All runs as made on the Gaudi node, from the repo root. On a CPU/GPU box, drop the launcher and use
`uv run python ... device=cpu|cuda`.

**The deep-well run** (the primary null). One worker per card (card 0 JE, card 1 MAE). It needs the MAE ViT-B/16 weights
(`encoder=vit_b16_mae`, mounted from `/mnt/cifar100`). The overlap-0 drives' `checkpoints/` are symlinked to a directory
with room for ~125 GB (mounted read-write):

```bash
BDD=/abs/path/to/bdd; CK=/abs/path/with/125GB; OUT=outputs/p110_deep
DIET="data=bdd data.split=val data.min_canary_count=50 bdd_root=$BDD device=hpu img_size=224 encoder=vit_b16_mae \
 stream.support_per_canary=45 stream.query_per_canary=45 stream.stratify_canary=true stream.well_fraction=0.5 \
 stream.select_support_per_canary=150 stream.select_query_per_canary=150"
run() { card=$1; shift; ./scripts/run_gaudi_dev.sh -m $BDD -m $CK:$CK -m /mnt/cifar100 gaudi-env-cafl4ds:latest $card "$@"; }

worker() {  # card, backbone, lr — the drive keeps the well's lr
  card=$1; bb=$2; lr=$3
  for o in 0.0 1.0; do
    run $card python scripts/warm_well.py $DIET backbone=$bb optim.lr=$lr stream.well_overlap=$o \
      warmup.stop=competence warmup.select_every=100 warmup.max_steps=6000 warmup.max_passes=100 \
      warmup.competence.window=1000 warmup.competence.tol=0.015 warmup.competence.min_steps=2000 \
      warmup.drive_read_per_class=500 well_out=wells/p110_deep/${bb}_o$o.pt hydra.run.dir=$OUT/wells/${bb}_o$o
  done
  for o in 0.0 1.0; do for order in walk iid; do
    name=${bb}_o${o}_$order; ckpt=false
    if [ "$o" = "0.0" ]; then ckpt=true; mkdir -p $OUT/warm/$name $CK/$name; ln -sfn $CK/$name $OUT/warm/$name/checkpoints; fi
    run $card python scripts/run_deploy_harness.py $DIET gate_arms=false eval_every=1 backbone=$bb optim.lr=$lr \
      stream.well_overlap=$o stream.order=$order well=wells/p110_deep/${bb}_o$o.pt checkpoint_legs=$ckpt \
      'seeds=[0,1,2,3,4]' study=P1.1.0 hydra.run.dir=$OUT/warm/$name
  done; done
}
worker 0 je 3e-5 & worker 1 mae 1e-4 & wait

uv run python scripts/analyze_null.py root=$OUT 'overlaps=[0.0,1.0]' 'cold_backbones=[]'
```

The ViT-B warm scout behind the recipe is the same `warm_well.py` call with `warmup.stop=budget warmup.max_steps=3000`,
`stream.select_*_per_canary=50`, and `encoder` ∈ {`vit_b16_pretrained` (mount `~/.cache/torch`), `vit_b16_mae`} × `lr` ∈
{1e-5, 3e-5, 1e-4}.

**The shallow sweep** (the five-level familiarity read) — one worker per card (card 0 JE + cold JE, card 1 MAE), each
warming its five wells and then driving them:

```bash
BDD=/abs/path/to/bdd   # images/100k/val/*.jpg + labels/bdd100k_labels_images_val.json
OUT=outputs/p110
DIET="data=bdd data.split=val data.min_canary_count=50 bdd_root=$BDD device=hpu img_size=64 \
 stream.support_per_canary=45 stream.query_per_canary=45 stream.stratify_canary=true stream.well_fraction=0.5"
run() { card=$1; shift; ./scripts/run_gaudi_dev.sh -m $BDD gaudi-env-cafl4ds:latest $card "$@"; }

worker() {  # card, backbone
  card=$1; bb=$2
  for o in 0.0 0.25 0.5 0.75 1.0; do   # the well and every drive share $DIET, so they reserve identically
    run $card python scripts/warm_well.py $DIET backbone=$bb stream.well_overlap=$o \
      well_out=wells/p110/${bb}_o$o.pt hydra.run.dir=$OUT/wells/${bb}_o$o
  done
  for o in 0.0 0.25 0.5 0.75 1.0; do for order in walk iid; do
    ckpt=false; [ "$o" = "0.0" ] && ckpt=true   # leg checkpoints at the primary level only
    run $card python scripts/run_deploy_harness.py $DIET gate_arms=false eval_every=1 backbone=$bb \
      stream.well_overlap=$o stream.order=$order well=wells/p110/${bb}_o$o.pt checkpoint_legs=$ckpt \
      'seeds=[0,1,2,3,4]' hydra.run.dir=$OUT/warm/${bb}_o${o}_$order
  done; done
}
worker 0 je & worker 1 mae & wait

# Cold JE (secondary), anchored to the disjoint JE well:
for order in walk iid; do
  run 0 python scripts/run_deploy_harness.py $DIET gate_arms=false eval_every=1 backbone=je stream.order=$order \
    well=null anchor=wells/p110/je_o0.0.pt checkpoint_legs=true 'seeds=[0,1,2]' hydra.run.dir=$OUT/cold/je_$order
done

# The analysis (CPU, seconds) — writes $OUT/null_report.json and prints the per-signal tables:
uv run python scripts/analyze_null.py root=$OUT
```

The competence table's rows come from `scripts/supervised_ceiling.py` (`epochs=0` for a probe-only read of an encoder as
built; `well=<path> backbone=<je|mae>` to read a saved well; `epochs>0` to train with labels).
