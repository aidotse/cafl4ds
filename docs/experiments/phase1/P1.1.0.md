# Healthy-movement null + canary probe power `[engineering + new runs]`

The first P1.1 sub-study (see the [Phase 1 overview](index.md)). Phase 0's load-bearing warning is that a healthy
backbone *also* moves its health instruments — a U-shaped RankMe dip, rising drift — for benign reasons
([P0.1.0](../phase0/P0.1.0.md), [P0.2.1](../phase0/P0.2.1.md)). So a reading off the correlated BDD drive means nothing
until we know how much a healthy, *uncorrelated* drive moves. This sub-study measures that **healthy-movement null**,
quantifies the labelled canary's statistical power (the P1.0 audit's C2), and checks whether the null depends on how
familiar the drive's frames are to the warm-start well.

## Motivation

Leg (b) of the exit gate asks whether streaming induces *measurable degradation*. The instruments move under any
training, so "the needle moved" is not evidence. What is evidence is a reading that moves *more than a healthy drive's
does*. That requires a healthy reference drive that differs from the real one in exactly one respect — the correlation —
so a gap between them can only come from the correlation.

Two further questions ride along, because P1.1.1 (the reading protocol) and P1.3 (forgetting) both lean on the answers:

- **Is the canary strong enough to be ground truth?** P1.0.2 left it as a thin channel (75 query images, mean a few
    points over chance). If it cannot resolve a realistic gap, it cannot arbitrate "degradation vs. benign" either.
- **Does familiarity shift the null?** A warm drive resumes a well. If the well already saw the drive's frames, the
    drive replays known images, which plausibly moves the model less. P1.3 will drive on BDD *train*, where frames are
    new — so a null measured on familiar frames could be too narrow and make benign movement there look like
    degradation.

## Methodology

### The matched IID control

`RegimeStream(order="iid")` delivers the **exact images** the regime walk delivers, at the walk's **per-step batch
sizes** and **step count**, shuffled across regimes (every batch tagged `era=0`). The walk and its control therefore
differ only in ordering. The shuffle draws from the drive seed's private generator *after* the walk is built, so it
cannot perturb the walk itself (verified by the independent review below). Comparisons are made checkpoint-for-
checkpoint on the shared step grid; the analysis refuses a pair whose checkpoint steps differ.

### Instrument fixes

- **Larger, stratified probe set.** Every instrument reads the same fixed probe-query set, so P1.0.2's 75 images capped
    RankMe at 75 and starved the canary. The probes are now reserved per **(time of day × scene)** cell — 45 support +
    45 query per cell, 9 cells — giving 405 query images pooled and 135 per stratum. The smallest val cell (dawn/dusk ×
    residential, 96 frames) sets that ceiling.
- **Per-stratum canary.** The monitor reports `knn_acc_<stratum>` / `linear_acc_<stratum>` (`daytime`, `dawn_dusk`,
    `night`) beside the pooled accuracy: one probe fit on the pooled support, scored per query stratum. This is the
    channel a forgetting read needs — "did daytime accuracy fall while the walk sat at night?" — which the pooled canary
    cannot see. The slices sit in the canary channel and inherit the pooled probe's trust verdict.
- **Drift anchored to the frozen well** (`anchor=`, defaulting to `well`), not to the run's first checkpoint — Phase 0's
    "fixed, independently-certified reference" principle. For a warm drive the well *is* the start state, so drift is
    read from step 0. Cold drives anchor to the JE well, which makes `cka_drift` a "distance from a competent reference"
    (`cosine_drift` is not meaningful across different coordinate frames).
- **Grad norm in the corpus** — the max pre-clip norm since the previous checkpoint, joined from the loss series.
- **Leg-boundary checkpoints** (`checkpoint_legs=true`) — the full method saved before each leg-opening step and at the
    end, for post-hoc reads too costly to run inline (P1.3's fine-tune probe). The IID control saves at the same steps.

### The well/drive split and the familiarity knob

`stream.well_fraction` reserves a fixed per-regime slice of the training pool for the well (drawn from `canary_seed`, so
identical across drives); the drive never streams it. `stream.well_overlap` then dials familiarity back in **without
moving anything else**: the well pool keeps its size, but that fraction of it is swapped for frames the drive also
streams. The drive — images, order, batching — is bit-identical at every overlap level, and higher levels swap in a
superset of lower levels' familiar frames. With `well_fraction=0.5` the well and drive pools are about the same size, so
the well-side and drive-side familiar fractions coincide (≈ the nominal overlap, up to per-regime rounding).

Sweeping `well_fraction` itself was considered and rejected: it is effectively on/off for familiarity (0 = shared, any
value > 0 = disjoint), while what it does vary — drive length and well data size — would confound the read.

### Statistics

All comparisons are walk vs. IID on the matched checkpoint grid, 5 seeds per arm.

- **Effect size.** Per checkpoint, *d* = (walk mean − IID mean) / pooled seed SD.
- **Significance.** An exact **seed-label permutation test**: all 252 ways to split the 10 seeds into two groups of 5,
    recomputing max-over-checkpoints |*d*| in each. Taking the max *inside* each split controls false alarms across the
    133 correlated checkpoints. The smallest attainable p is 2/252 ≈ 0.008. `frac_sig` is the share of checkpoints
    individually significant under that family-wise control.
- **Canary power.** The minimal detectable walk-vs-IID gap (two-sided 5%, 80% power) is
    `(t₀.₉₇₅ + t₀.₈₀; df = 8) · sd_seed · √(2/5)`, with `sd_seed` the root mean across-seed variance. The Wilson 95%
    interval on a single reading is reported separately.

These definitions replaced a first draft (a raw "z" read against 1.96, an envelope-exceedance fraction, and a
normal-quantile MDD) after the independent code review; the permutation test is unit-tested to hold its level on
autocorrelated null trajectories.

### The runs

BDD100K val at 64 px (8,753 images after dropping rare scenes), tiny ViT (embed 96, depth 4, patch 8), batch 32, AdamW.
`well_fraction=0.5` leaves a **133-step drive over 18 legs** (with the well slice carved out, the lone `dawn/dusk·foggy`
frame now stays in the drive as a one-batch leg, where P1.0.2 streamed 17 legs). Wells were warmed with the existing
loss-plateau rule.

- **Warm:** {JE, MAE} × 5 overlap levels {0, 0.25, 0.5, 0.75, 1} × {walk, IID} × 5 seeds — 10 wells, 20 drives.
- **Cold (secondary):** JE × {walk, IID} × 3 seeds, anchored to the overlap-0 JE well.

All 106 seed reports pass both P1.0.2 validation tiers. On two Gaudi2 cards the sweep took 2.5 h (wells ~1 min each,
~2.5 min per drive seed).

**The deep-well re-run** (the primary null) keeps the diet, split and statistics, and changes only the backbone and the
well. The backbone is a pretrained ViT-B/16 at 224 px, from the MAE checkpoint for both JE and MAE. The well is warmed
on the well pool until its selection-set competence stops moving (the recipe and why are in the handover, step 2). JE
trains at lr 3e-5 and MAE at 1e-4, in the well and the drive alike.

- **Deep:** {JE, MAE} × overlap {0, 1} × {walk, IID} × 5 seeds — 4 wells, 40 drive seeds. Overlap 0 saves leg
    checkpoints.
- The larger selection set (150 + 150 per scene) shortens the drive to **119 steps** over the same 18 legs (3,522
    frames; the well pool keeps 3,521).

All 40 seed reports pass both validation tiers. On two cards the wells took ~15–20 min each and a drive seed ~26 min (~9
h in all).

## Findings — the deep-well null

**The wells are deep now.** Each stopped on the two-sided competence plateau after 2,000–2,500 steps (~18–23 passes over
the 3,521-frame well pool). On the measurement probes they read:

| Well | kNN | Linear |
| -- | -- | -- |
| JE, overlap 0 / 1 | 0.53 / 0.53 | 0.63 / 0.60 |
| MAE, overlap 0 / 1 | 0.50 / 0.44 | 0.54 / 0.55 |

That is 0.11–0.30 above chance (0.33) and 0.11–0.30 below the fine-tuned ceiling (~0.74), so the canary has room to move
both ways. The shallow wells read 0.35–0.45.

**1. The healthy null is now nearly still.** This is the clearest change. Under IID, the deep JE well's projector RankMe
ends where it started (10.38 → 10.38), where the shallow well's fell by a quarter (5.4 → 4.0). Drift from the well stays
small (`cka_drift` ≤ 0.014 for JE and ≤ 0.03 for MAE, at overlap 0). So most of the shallow null's "benign movement" was
the well still settling. A well warmed to its plateau gives a quiet reference. The movement Phase 0 warned about is
real, but it is mostly a property of an unsettled start.

**2. JE: the walk still compresses the projector, and now it also moves drift — the canary stays flat.**

| Overlap | `rankme_proj` IID / walk (end) | Peak IID / walk ratio | `cka_drift` IID / walk (end) | Canary gap, kNN / linear (p) |
| -- | -- | -- | -- | -- |
| 0 | 10.38 / 8.30 | 1.66× | 0.012 / 0.127 | +0.003 / +0.029 (0.87 / 0.16) |
| 1 | 9.89 / 8.59 | 1.75× | 0.033 / 0.132 | +0.010 / +0.001 (0.42 / 0.96) |

- The projector readers separate walk from IID at both levels (`rankme_proj` p ≤ 0.016, `uniformity_proj` p = 0.008,
    final *d* +3.2 to +4.9). The backbone's own RankMe now separates too at overlap 0 (p = 0.008, 31% of checkpoints
    significant), which it barely did on the shallow wells.
- **Drift is new.** On the shallow wells JE's drift did not separate (p ≥ 0.14). On the deep wells the walk ends ~4–10×
    further from the well than IID, on both drift readers (p = 0.008 at both levels, significant at 46–74% of
    checkpoints).
- **The magnitude dropped below Phase 0's bar.** The peak IID/walk RankMe ratio is 1.66–1.75×, under the 2.0× firing bar
    the shallow wells reached (1.95–2.43×). The relative effect is smaller because the deep projector has more
    dimensions to lose (RankMe ~10 vs ~5).
- **The canary is flat, and now that means something.** The walk-vs-IID canary gaps are within ±0.03, never significant,
    and the walk is on the *higher* side where they differ. The walk's canary does not fall below its start either (JE
    linear 0.629 → 0.618, against an MDD of 0.038). With 0.2+ points of headroom, "no loss within ~3–4 points" is now a
    real statement, not a floor effect.

**3. MAE: the correlation leaves almost no trace.** On the deep wells, walk and IID are nearly indistinguishable.
Backbone RankMe does not separate (p = 0.08 / 0.18). The drift readers clear p ≤ 0.04 at overlap 0, but the gaps are
tiny (≤ 0.004 at the end). The canary gaps are ≤ 0.003. The shallow MAE wells had shown large drift separations (walk
`cka_drift` 0.38 vs IID 0.06). Those are gone at depth. Read with Phase 0's caveat that MAE's geometry is not a quality
reader, the verdict is unchanged and stronger: **MAE resists** the correlated drive at this horizon.

**4. Familiarity still has no visible effect.** Overlap 0 and 1 tell the same story on both backbones: JE's projector
and drift separation at both levels, MAE quiet at both. The caveat from the shallow sweep remains: one well per level.

**5. Canary power at depth.** Seed spread stays small, so the paired contrast resolves:

| Read | Mean | Seed SD | MDD (5 vs 5 seeds) |
| -- | -- | -- | -- |
| Pooled, JE (kNN / linear) | 0.52–0.53 / 0.60–0.61 | 0.012–0.022 | 0.024–0.045 |
| Pooled, MAE (kNN / linear) | 0.47 / 0.55–0.56 | 0.011–0.016 | 0.021–0.032 |
| Per stratum (both) | — | — | 0.036–0.075 |

A handful of individual strata clear p < 0.05 (JE daytime kNN at overlap 0, JE night kNN at overlap 1, MAE daytime kNN
at overlap 0). Every one has the walk *ahead* by 0.02–0.03, and none recurs across levels. There is no forgetting
signature.

**6. Two reading caveats, both matched across arms.**

- **The last checkpoint is a 3-image batch.** The walk's last leg ends on 3 frames, and the IID control copies the
    walk's batch sizes. A 3-image SSL loss and grad norm are noisy. For example, the JE IID loss is flat at −0.97 for
    118 steps and reads −0.63 at the last one, with grad norm jumping from ~0.3 to ~9. So read `loss` and `grad_norm`
    off max |*d*| and `frac_sig`, not their endpoints. The shallow sweep's endpoints carry the same artifact; its loss
    and grad-norm findings rest on p and max |*d*|, so they stand. Loss and grad norm still separate walk from IID
    mechanically (p ≤ 0.016), as before.
- **The drive restarts the optimizer.** A well stores the model, not AdamW's moment estimates, so the drive begins with
    a fresh optimizer. MAE's grad norm jumps 1.1 → 8.1 on the first step and settles within ~5 steps. The JE canary dips
    ~0.02 in the first 10 steps on both arms. Both arms share the transient, so it cancels in the contrast. A later
    study reading absolute movement from step 0 should either save the optimizer state with the well or skip the first
    ~10 steps.

## Findings — the shallow-well null (the familiarity sweep)

**The wells are shallow.** The loss-plateau rule stops after 98–140 steps — under one pass over the ~4,000-image well
pool — at a canary of kNN 0.35–0.42 / linear 0.42–0.45 against chance 0.33. Every number below is read off these wells.
The [deep-well null](#findings--the-deep-well-null) above supersedes it as the primary result; this sweep stays as the
five-level familiarity read. The step-2 competence study showed that "shallow" understates it. Read on 3,800 held-out
frames, these wells score at the level of a *randomly initialized* encoder (see
[Remaining work](#remaining-work--handover), step 2).

**1. Even the healthy null moves a lot.** Under IID, JE's projector RankMe falls from ~5.4–6.2 to ~3.5–4.0 over the
drive, and both backbones' drift climbs. This is the benign movement Phase 0 warned about, now measured on BDD.

**2. JE: the walk moves the collapse readers to the Phase-0 bar's magnitude, at every familiarity level — the canary
stays flat.**

| Overlap | `rankme_proj` IID / walk (end) | Peak IID / walk ratio | p (`rankme_proj`) |
| -- | -- | -- | -- |
| 0 | 4.02 / 2.19 (1.83×) | 2.43× | 0.008 |
| 0.25 | 3.79 / 1.97 (1.92×) | 2.43× | 0.008 |
| 0.5 | 3.51 / 2.28 (1.54×) | 2.13× | 0.016 |
| 0.75 | 3.80 / 2.09 (1.82×) | 2.26× | 0.008 |
| 1 | 3.80 / 2.40 (1.58×) | 1.95× | 0.008 |

- The other calibrated projector readers agree: lower `mean_feature_var_proj` and `offdiag_cov_proj`, higher
    `uniformity_proj` (p ≤ 0.024 at every level). The backbone surface barely separates (`rankme` p = 0.04 at overlap 0
    only), matching Phase 0's "gate on the projector" finding.
- The effect is strongest on the **night legs** (mean *d* ≈ −3.5, vs. −2.3 daytime and −1.7 dawn/dusk). Dark,
    low-diversity frames are the case Jing (2022) predicts is most susceptible to dimensional collapse.
- The **canary does not move**: no checkpoint is individually significant for pooled kNN or linear accuracy at any
    level, and the final gaps sit within ±0.02.
- The caveat: Phase 0's 2.0× bar was calibrated at toy scale as a PC-vs-healthy ratio, so reaching its magnitude here is
    not a calibrated fire. Whether this is genuine collapse the 3-class canary cannot see, or benign compression, is
    exactly the discrimination P1.1.1 owns.

**3. MAE: the internals move, the canary does not — MAE resists again.** The walk lowers backbone RankMe (final *d* −1.5
to −2.6; significant at 3/5 levels) and raises drift (`cosine_drift` p ≤ 0.032 at every level). Phase 0 showed MAE's
geometry is not a quality reader ([P0.5](../latest-results/P0.5.md)), so these are not evidence of harm on their own.
The forgetting signature is absent: pooled across levels, daytime canary accuracy does **not** fall during the night
legs (linear *d* ≈ −0.02, kNN ≈ −0.30). Individual stratum slices occasionally clear the permutation test, but their
direction flips between levels — sporadic, not systematic.

**4. Loss and grad norm separate mechanically.** The loss differs walk-vs-IID at every level on both backbones (p ≤
0.016), grad norm at every JE level and 2/5 MAE levels. This is a property of the diet — walk batches come from a single
regime, IID batches mix all of them — not a health signal. Neither should be read as degradation.

**5. Familiarity has no detectable effect on the null.** No signal's IID movement trends across the five overlap levels
(Spearman over levels, all p ≥ 0.23), and the JE projector effect appears at every level. Two caveats bound this: there
is **one well per level**, so a level cannot be separated from its well draw (the MAE overlap-0 well is the most
competent, kNN 0.41 vs. 0.35–0.37, and also shows the largest MAE walk-vs-IID effects); and at these shallow wells
"familiar" means *seen about once*, so the sweep rules out only a large familiarity effect.

**6. Canary power (audit C2).** Every arm reads the *same* fixed probe images, so the sampling error of a finite probe
set is shared and cancels in a walk-vs-IID contrast. What limits the contrast is the seed-to-seed spread, which is small
(overlap 0, both backbones):

| Read | Mean | Seed SD | MDD (5 vs 5 seeds) | Wilson 95% (one reading) |
| -- | -- | -- | -- | -- |
| Pooled (kNN / linear) | 0.38–0.43 | 0.013–0.019 | 0.025–0.039 | ±0.05 |
| Per stratum | 0.36–0.44 | 0.023–0.040 | 0.047–0.081 | ±0.08 |

So the canary resolves a walk-vs-IID gap of ~3–4 points pooled and ~5–8 points per stratum, and the observed gaps sit
below that: "no canary loss, to within ~3 points". The Wilson interval matters only for generalizing a reading to all of
BDD, not for the paired contrast. The remaining limitation is headroom, not power: at 0.38–0.44 against chance 0.33, a
shallow well has little room to show a loss.

**7. A healthy AdamW run can spike its grad norm.** One IID drive (JE, overlap 0.75, seed 2) logged a single grad norm
of 290 against a median of 0.11, with no divergence. This matters if grad norm is ever used as an alarm on this recipe
(cf. [P0.4](../latest-results/P0.4.md): its early warning is optimizer-contingent).

**Cold JE (secondary).** The same direction as warm (`rankme_proj` final *d* −2.6, `uniformity_proj` +4.5), but 3 + 3
seeds allow only 20 splits, so p cannot fall below 0.10. It stays descriptive unless seeds are added.

## Code validity

An independent subagent review of the P1.1.0 code (scratch checks on the synthetic source) verified: the IID control
matches the walk exactly across batch sizes, `drop_last` and `block_size`; probes are balanced and disjoint from drive
and well at every overlap level and drive seed; the drive is identical across overlap levels; leg checkpoints capture
the state after exactly *s* completed batches; anchoring and per-stratum masks are correct; and the grad-norm windowing
is right. Its statistical findings were fixed before analysis (see [Statistics](#statistics)). Its latent harness
findings did not fire in this sweep; they were fixed after it (handover step 1).

One of those fixes could have touched a number: the sweep read its drift anchor on CPU while the drive ran on HPU.
Re-reading the overlap-0 wells' probe embeddings on both devices puts that floor at ≤ 1.2e-7 in `cka_drift` and 0 in
`cosine_drift` (max element difference ~1.5e-4), so the shallow-sweep drift numbers stand.

## Remaining work — handover

P1.1.0's null is tied to the wells it was measured from, and those are shallow. P1.1.1 needs a canary with headroom (the
surgical dose curve and the JE collapse-vs-benign question both read losses against it), so the substudy closes on a
**deep-well null**. The shallow sweep stays as the familiarity result. The steps, in order:

1. ✅ **Apply the review's harness fixes** (done; none changes a shallow-sweep number — see
    [Code validity](#code-validity)). What changed for the runs below:
    - Leg checkpoints index `batches_seen`, write `index.json` even on an early stop, and refuse a second pass.
    - The drift anchor is read on `config.device`.
    - Each report header carries the realized `familiarity` (`well_side` / `drive_side`) and `n_probe_query` (pooled and
        per stratum); `analyze_null.py` reads the latter from the run, keeping `null_envelope.yaml`'s counts only as a
        fallback for older corpora.
    - `warm_well.py` writes `<well>.split.json` (probe + well-slice fingerprint) and the drive refuses a well (or anchor)
        reserved differently. The shallow wells predate this, so driving them only warns.
    - The monitor warns when an anchor lacks a surface the run tracks; `with_grad_norm` is linear-time; the study label
        is the `study` config key (default `P1.0.2` — pass `study=P1.1.0`).
1. ✅ **Add a labelled selection set and scout the competence ceiling.**
    - *Why a separate set.* The well must be (i) well above chance and (ii) on its competence plateau, so continued
        learning neither masks nor mimics a loss (the [P0.3.10](../phase0/P0.3.10.md) lesson). The SSL loss is not a
        competence signal for MAE ("the loss lies", [P0.5](../latest-results/P0.5.md)). Stopping on the measurement
        canary would select on noise, and the drive's regression to the mean would then look like degradation.

    - *The set.* A third reservation of ~50 images per scene, **pooled** over time of day (the smallest stratified cell
        is already almost fully used by the probes), drawn from `canary_seed`, disjoint from probes, well pool and drive.
        Used only to stop the well. `warm_well.py` logs its kNN / linear accuracy every ~50 steps.

    - *The scout.* Warm JE and MAE for a long fixed budget (~3,000 steps ≈ 25 passes) and log the selection canary and
        SSL loss over time. Sweep **resolution** as the first axis — `img_size` ∈ {64, 96, 128} (patch 8 → an 8/12/16
        grid; eager BDD decode at 128 px is ~1.7 GB). The working hypothesis is that 64 px strips the cues a scene
        representation needs, and that the 4-layer ViT is not the binding constraint.

    - *Decide.* Pick `img_size` and a competence stopping rule from the curves (e.g. stop when selection kNN improves by
        < 1 point over 500 steps, with a step cap). If the ceiling stays low at every resolution, bring the model-size
        question back to the user before proceeding. A resolution change changes the substrate, so the whole null is
        re-run at the new resolution (step 3).

    - *Watch for* overfitting the ~4,000-image well pool under many passes — it would make the drive's new frames more
        unfamiliar than in the shallow sweep, which is what step 3's familiarity check probes.

    - ✅ **Done: engineering, the competence study, and the ViT-B warm scout; the deep-well recipe is decided.**

        - *Engineering.* `stream.select_{support,query}_per_canary` reserve the selection set; `warm_well.py` takes
            `warmup.stop=loss|competence|budget` and `warmup.select_every`, and writes `<well>.trace.json`.
            `scripts/supervised_ceiling.py` gives every encoder the same competence read (below), and can also train the
            encoder with labels.
        - *The scout first.* Both backbones × 64/96/128 px × 3,000 steps showed no trend on the 150-image selection query.
            That set turned out too noisy (~±0.04) to see a 5-point gain, so every well was re-read on a tighter protocol.
        - *The protocol.* Probes are fit on a class-balanced subsample of the well pool (500 per scene). They are scored by
            **balanced accuracy** on the drive pool: ~3,800 labelled frames no encoder trains on. Chance is 0.33.
            Supervised rows report the trained head's best drive-pool score instead.

        | Encoder | Training | kNN | Linear (or head) |
        | -- | -- | -- | -- |
        | Tiny ViT, random init | none | 0.41–0.43 | 0.46 |
        | Shallow sweep wells (overlap 0) | SSL, 98–140 steps | JE 0.45 · MAE 0.42 | JE 0.48 · MAE 0.47 |
        | Scout wells, 64–128 px | SSL, 3,000 steps on the well pool | JE 0.42–0.45 · MAE 0.48–0.50 | JE 0.48 · MAE 0.50–0.54 |
        | BDD-train wells, 64 px | SSL, 20,000 steps on 61k IID train frames | JE 0.44 · MAE 0.50 | JE 0.47 · MAE 0.54 |
        | Tiny ViT, supervised | labels, 30 epochs (64 / 128 px) | — | head 0.51 / 0.51 |
        | … at lr 1e-4 / 3e-4, or on CPU | labels, 30 epochs, 64 px | — | head 0.53 / 0.51 / 0.51 |
        | … with 30k labelled train frames | labels, 15 epochs, 64 px (scored on 30k held-out train frames) | — | head 0.50 |
        | ViT-B/16 ImageNet-supervised, frozen | none (64 / 224 px) | 0.61 / 0.64 | 0.56 / 0.62 |
        | ViT-B/16 MAE, frozen | none (64 / 224 px) | 0.52 / 0.53 | 0.58 / 0.63 |
        | ViT-B/16, fine-tuned with labels | labels, 224 px (ImageNet / MAE init) | — | head 0.75 / 0.74 |

        - **The task is learnable, and the frames carry the signal.** A labelled ViT-B reaches ~0.74; that is the practical
            ceiling the canary labels allow (scene labels are noisy — residential vs. city street is a fuzzy call). Frozen
            pretrained features already reach 0.56–0.64 without seeing BDD.
        - **The tiny from-scratch ViT is the binding constraint.** With labels it tops out at ~0.50–0.53, and it does not
            even fit its training set (train balanced accuracy ≤ 0.61). Eight times the labelled data, a lower learning
            rate, or a higher resolution do not change that. A CPU run matches the HPU one, so this is not a device
            artifact.
        - **Within that ceiling, MAE already does as well as supervision; JE does not learn.** MAE wells reach 0.50 / 0.54
            — the tiny model's supervised level. More data (BDD train) adds only ~2–4 points. SimSiam (JE) stays at the
            random-encoder level everywhere, while its loss saturates.
        - **The shallow sweep's wells sit at the random level** (row 2), so its canary had essentially no competence to
            lose. This sharpens finding 6's headroom caveat.
        - **Decided (2026-10-13): deep wells on a pretrained ViT-B/16** (ImageNet-supervised `encoder=vit_b16_pretrained`
            and MAE `encoder=vit_b16_mae`; both on disk). It is the only option that leaves the canary room to fall (frozen
            0.56–0.64 against a 0.74 ceiling) and that gives JE a representation to lose. The alternatives — a small CNN
            from scratch, or a larger from-scratch ViT — stay untested, in reserve.
        - **The reference point is the *warmed* checkpoint, not the pretrained one** (the P0.3.9 / P0.3.10 lesson).
            Continued SSL on in-domain data — new SSL heads (fresh-head transient), a new learning rate, a new loss — is
            expected to pull competence *down* from the pretrained optimum before it settles. The drive must start where
            the warm-up's competence has stabilized, so a later fall is the drive's doing and not the end of that settling.
            So the deep well stops on `warmup.stop=competence`, never on the pretrained checkpoint or the loss.
        - **The ViT-B warm scout (224 px, 3,000 steps, lr ∈ {1e-5, 3e-5, 1e-4}) confirms the dip and fixes the recipe.**
            The warm-up now logs the drive-pool read beside the selection read (`warmup.drive_read_per_class`, a diagnostic
            only; it never stops a well). Settled levels, drive pool, kNN / linear:

        | Backbone · init | Best lr | Start | Settled (steps 2,000–3,000) |
        | -- | -- | -- | -- |
        | JE · ImageNet-supervised | 3e-5 | 0.64 / 0.62 | 0.57 / 0.65 |
        | JE · MAE | 3e-5 | 0.53 / 0.63 | 0.55 / 0.64 |
        | MAE · MAE | 1e-4 | 0.53 / 0.63 | 0.53 / 0.55 |

        - Every run dips in its first 100–500 steps and levels off by ~1,500–2,000. JE's linear read recovers to slightly
            above its start. MAE's does not: it settles ~0.07 below while its loss keeps falling — "the loss lies" again.
            Both still sit far above the tiny-ViT wells (~0.45 / 0.48) and below the 0.74 ceiling, so the canary has room
            to fall.
        - **The 150-image selection read is mostly noise on the plateau.** Its reading-to-reading jitter is 0.025–0.035,
            against ~0.01 for the drive-pool read, and the two barely correlate (r ≈ 0–0.4). So the deep wells reserve
            **150 + 150 per scene** (the smallest scene, residential, has 1,253 frames).
        - **The stop rule is two-sided** (`CompetenceCriterion.tol`, which replaces `min_gain`). Several runs keep
            *sliding* after the dip, and a rule that only waits out gains would stop mid-slide — the drive would then
            inherit the rest of the slide as an apparent loss. Replayed on the scout traces, a 1,000-step window stops at
            ~2,000–2,800 steps, on the plateau.
        - **Decided (2026-10-13), the deep-well recipe:** both backbones from the **MAE init** (`encoder=vit_b16_mae`) —
            label-free end to end, and one shared starting point, at a JE plateau within 0.03 of the ImageNet init's. JE lr
            3e-5, MAE lr 1e-4, and the drives keep the well's lr. `img_size=224`. `warmup.stop=competence`,
            `select_every=100`, competence `{key: knn_acc, window: 1000, tol: 0.015, min_steps: 2000}`, `max_steps=6000`.
        - Artifacts: [`artifacts/P1.1.0/scout/`](artifacts/P1.1.0/scout/) (selection traces) and
            [`artifacts/P1.1.0/competence/`](artifacts/P1.1.0/competence/) (one `supervised_ceiling.json` per row, plus the

## How to run

The sweep as run on the Gaudi node — one worker per card (card 0 JE + cold JE, card 1 MAE), each warming its five wells
and then driving them. Run from the repo root; on a CPU/GPU box drop the launcher and use
`uv run python ... device=cpu|cuda`.

```bash
BDD=/abs/path/to/bdd   # images/100k/val/*.jpg + labels/bdd100k_labels_images_val.json
OUT=outputs/p110
DIET="data=bdd data.split=val data.min_canary_count=50 bdd_root=$BDD device=hpu img_size=64 \
 stream.support_per_canary=45 stream.query_per_canary=45 stream.stratify_canary=true stream.well_fraction=0.5"
run() { card=$1; shift; ./scripts/run_gaudi_dev.sh -m $BDD gaudi-env-cafl4ds:latest $card "$@"; }

worker() {  # card, backbone
  card=$1; bb=$2
  for o in 0.0 0.25 0.5 0.75 1.0; do   # the well and every drive share $DIET, so they reserve identically
    run $card python scripts/warm_well.py $DIET backbone=$bb stream.well_overlap=$o \
      well_out=wells/p110/${bb}_o$o.pt hydra.run.dir=$OUT/wells/${bb}_o$o
  done
  for o in 0.0 0.25 0.5 0.75 1.0; do for order in walk iid; do
    ckpt=false; [ "$o" = "0.0" ] && ckpt=true   # leg checkpoints at the primary level only
    run $card python scripts/run_deploy_harness.py $DIET gate_arms=false eval_every=1 backbone=$bb \
      stream.well_overlap=$o stream.order=$order well=wells/p110/${bb}_o$o.pt checkpoint_legs=$ckpt \
      'seeds=[0,1,2,3,4]' hydra.run.dir=$OUT/warm/${bb}_o${o}_$order
  done; done
}
worker 0 je & worker 1 mae & wait

# Cold JE (secondary), anchored to the disjoint JE well:
for order in walk iid; do
  run 0 python scripts/run_deploy_harness.py $DIET gate_arms=false eval_every=1 backbone=je stream.order=$order \
    well=null anchor=wells/p110/je_o0.0.pt checkpoint_legs=true 'seeds=[0,1,2]' hydra.run.dir=$OUT/cold/je_$order
done

# The analysis (CPU, seconds) — writes $OUT/null_report.json and prints the per-signal tables:
uv run python scripts/analyze_null.py root=$OUT
```

**The deep-well re-run** (the primary null). One worker per card (card 0 JE, card 1 MAE). It needs the MAE ViT-B/16
weights (`encoder=vit_b16_mae`, mounted from `/mnt/cifar100`). The overlap-0 drives' `checkpoints/` are symlinked to a
directory with room for ~125 GB (mounted read-write):

```bash
BDD=/abs/path/to/bdd; CK=/abs/path/with/125GB; OUT=outputs/p110_deep
DIET="data=bdd data.split=val data.min_canary_count=50 bdd_root=$BDD device=hpu img_size=224 encoder=vit_b16_mae \
 stream.support_per_canary=45 stream.query_per_canary=45 stream.stratify_canary=true stream.well_fraction=0.5 \
 stream.select_support_per_canary=150 stream.select_query_per_canary=150"
run() { card=$1; shift; ./scripts/run_gaudi_dev.sh -m $BDD -m $CK:$CK -m /mnt/cifar100 gaudi-env-cafl4ds:latest $card "$@"; }

worker() {  # card, backbone, lr — the drive keeps the well's lr
  card=$1; bb=$2; lr=$3
  for o in 0.0 1.0; do
    run $card python scripts/warm_well.py $DIET backbone=$bb optim.lr=$lr stream.well_overlap=$o \
      warmup.stop=competence warmup.select_every=100 warmup.max_steps=6000 warmup.max_passes=100 \
      warmup.competence.window=1000 warmup.competence.tol=0.015 warmup.competence.min_steps=2000 \
      warmup.drive_read_per_class=500 well_out=wells/p110_deep/${bb}_o$o.pt hydra.run.dir=$OUT/wells/${bb}_o$o
  done
  for o in 0.0 1.0; do for order in walk iid; do
    name=${bb}_o${o}_$order; ckpt=false
    if [ "$o" = "0.0" ]; then ckpt=true; mkdir -p $OUT/warm/$name $CK/$name; ln -sfn $CK/$name $OUT/warm/$name/checkpoints; fi
    run $card python scripts/run_deploy_harness.py $DIET gate_arms=false eval_every=1 backbone=$bb optim.lr=$lr \
      stream.well_overlap=$o stream.order=$order well=wells/p110_deep/${bb}_o$o.pt checkpoint_legs=$ckpt \
      'seeds=[0,1,2,3,4]' study=P1.1.0 hydra.run.dir=$OUT/warm/$name
  done; done
}
worker 0 je 3e-5 & worker 1 mae 1e-4 & wait

uv run python scripts/analyze_null.py root=$OUT 'overlaps=[0.0,1.0]' 'cold_backbones=[]'
```

The ViT-B warm scout behind the recipe is the same `warm_well.py` call with `warmup.stop=budget warmup.max_steps=3000`,
`stream.select_*_per_canary=50`, and `encoder` ∈ {`vit_b16_pretrained` (mount `~/.cache/torch`), `vit_b16_mae`} × `lr` ∈
{1e-5, 3e-5, 1e-4}.
