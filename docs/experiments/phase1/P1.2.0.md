# The readout ladder and the frozen floor, read on P1.1's artifacts `[engineering + analysis]` (P1.2.0)

**What this substudy is.** The first P1.2 sub-study (see the [Phase 1 overview](index.md)). P1.2 asks leg (a) of the
exit gate: does a backbone that keeps learning on the stream beat the same backbone frozen (**B5**)? P1.2.0 builds the
instruments that question needs and points them at what P1.1 already left on disk. It is a scout, not the gate. The gate
read is [P1.2.1](P1.2.1.md), on a horizon long enough to give adaptation a fair chance.

## Motivation

**B5, made concrete.** The plan defines B5 as the frozen, *init-matched* backbone: frozen-pretrained in the pretrained
regime ([experiments.md](../../project-plan/experiments.md#evaluation)). Here that is the off-the-shelf MAE ViT-B/16
checkpoint, read with no BDD training at all. The harness's existing `b5` gate arm is something else. It freezes the
*well*, which has already trained offline on BDD for ~2,000–2,500 steps. That answers a deployment question ("should we
have stopped training at deployment time?"), not the plan's question ("does adapting beat doing nothing?"). Both
framings are read here; the gate uses the plan's.

**Why a scout first.** Three things in P1.1's record bear directly on leg (a), and none was measured for it.

- **Continued SSL lowered MAE's frozen probes.** In P1.1.0's ViT-B warm scout, MAE training pulled the drive-pool linear
    read from 0.63 to ~0.55 while its loss kept falling. JE stayed level. So on frozen probes, the frozen backbone may
    already beat adaptation.
- **Frozen probes understate MAE.** Phase 0 found MAE's quality shows under fine-tuning more than under linear
    separability. A fine-tune rung could reverse the reading above. No fine-tune read of these models exists.
- **The dip may be a head artifact.** The MAE checkpoint is encoder-only, and SimSiam heads matched to it do not exist.
    So every warm-up so far bolted *random* heads onto a pretrained encoder and trained both together. That is the
    textbook setting in which early gradients from a random head distort pretrained features (Kumar et al. 2022, the
    case for linear-probing-then-fine-tuning). [P0.3.6](../phase0/P0.3.6.md) measured the same cost (0.89 → 0.65–0.71
    while warming a fresh decoder). P1.1.0's "settled-well lesson" — continued training first pulls quality down, then
    levels off — was always measured this way. Whether the dip is intrinsic to continued SSL or mostly a head transient
    is open.

**What is not in question.** P1.1's contrasts all started from wells whose heads had trained for 2,000+ steps, so the
null, the walk-vs-IID contrasts and the canary's power stand. Phase 0's arm contrasts shared their head transient, so it
cancelled. Only the *interpretation* of the dip is at stake.

## Design

Four parts. All read **frozen or fine-tuned encoders offline**, after the fact, on the same evaluation sets.

### 1. The readout ladder (engineering)

A new reader, `scripts/read_adaptation.py`, scores any encoder — the off-the-shelf weights, a random init, a saved well,
or a leg checkpoint — on the plan's ascending-label ladder:

- **kNN** (k = 20) and **linear probe** (logistic regression) on frozen features, as the canary computes them.
- **Few-shot fine-tune** — the encoder and a linear head on its pooled embedding trained together on *k* labelled images
    per class, *k* ∈ {10, 100}, three label draws each (draw *d* uses the same images for every encoder, so draws pair
    across encoders). AdamW, weight decay 0.05, 150 steps, batch ≤ 32, horizontal flips, cosine schedule, head lr 10×
    the encoder's. It reuses `supervised_ceiling.py`'s classifier.

Every reading is **balanced accuracy** (the mean of per-class recalls, so a majority class cannot inflate it), pooled
and per time-of-day stratum. The reader saves **per-image correctness**, so a contrast can be resampled over images as
well as seeds.

**The few-shot learning rate is fixed once, on B5.** The grid {1e-5, 3e-5, 1e-4} is scored on B5 at *k* = 100 against a
validation reservation (200 images per class, disjoint from the fit subsample and the query set). The winner is used for
every encoder from then on. Tuning on B5 favours B5 slightly, which is the conservative direction for a claim that
adaptation beats it.

### 2. Evaluation sets

- **The held-out pool (primary for P1.2.0).** The P1.1 models trained only on BDD *val*, so BDD *train* is entirely
    unseen by them. The reader takes the first 14,000 attribute-valid train images of the three canary scenes
    (label-file order, which is hash-named and so effectively random) and splits them by a fixed seed: **40% fit pool,
    60% query** (~8,400 images). Per task, probes fit on a class-balanced subsample of the fit pool (500 per class). A
    query set this size puts the image-sampling error near ±0.01, against ±0.05 on the canary's 405 images.
- **The canary probes (continuity).** The P1.1.0 canary — 45 + 45 images per (time of day × scene) cell of val, never
    trained on — so P1.2.0's numbers line up with P1.1's.

BDD val is **not** used for P1.2.0's screens: it is P1.2.1's gate set, and stays unread until then.

### 3. The head-settle scout

Does the dip survive once the heads have settled? Two `warm_well.py` steps per backbone, on P1.1.0's deep diet (val,
`well_fraction=0.5`, overlap 0), one seed, as the original scout:

1. **Settle the heads.** The MAE weights, encoder **frozen** (`warmup.freeze_encoder=true`, new), heads trained at lr
    3e-4 until the SSL loss plateaus (window 200, tolerance 0.002, at least 500 and at most 3,000 steps). With the
    encoder frozen, the loss is the right stopping signal — nothing else is changing. A selection read every 100 steps
    must stay **bit-constant** (a correctness check that the encoder really is frozen).
1. **Unfreeze and continue.** Resume that well (`resume_well=`, new), all parameters trainable at the P1.1 recipe (JE
    3e-5, MAE 1e-4), for 1,000 steps, logging the drive-pool read (`warmup.drive_read_per_class=500`) every 25 steps.

**The read (fixed now).** For each backbone and frozen rung, the *dip* is the start reading minus the mean reading over
steps 100–500 (five common readings with the original scout's trace). Call the dip

- **mostly a head transient** if the settled-head dip is ≤ 0.02 on both rungs (about twice the drive read's jitter);
- **genuine** if the settled-head dip is at least half the fresh-head dip on either rung;
- **partly a head transient** otherwise.

**What it decides.** P1.2.1 uses a settled-head start whatever the outcome, so the scout changes interpretation, not
design. If the dip is mostly a head transient, P1.1.0's settled-well lesson gets a one-line qualification. If it is
genuine, adaptation starts in a hole it must climb out of, and P1.2.1's Δ(t) is read with that in view. One stop: if the
heads-only loss does not plateau within 3,000 steps, the settled-head start is not cheap, and P1.2.1's design comes back
for a decision.

### 4. The secondary readout task

The scene canary has little headroom: frozen-pretrained sits at ~0.63 linear and a fully fine-tuned ViT-B at ~0.74. A
No-Go resting on that one task could mean only that the task is saturated. So P1.2.1 carries a second task, chosen here,
before its data is read.

- **Candidates.** Object presence from BDD's box labels, one binary task per class: **traffic light** (present in 56% of
    train images), **pedestrian** (32%), **truck** (27%). The source already parses per-image box counts
    (`object_categories`).
- **Measured per candidate**, on the held-out pool:
    - *headroom* — a full-label fine-tune ceiling (1,500 images per class, 20 epochs, the `supervised_ceiling.py` recipe)
        minus B5's linear read;
    - *overlap with the scene* — the balanced accuracy of predicting presence from the scene label (and time of day)
        alone, by a logistic regression on their one-hots.
- **The rule (fixed now).** A candidate is eligible if its overlap is ≤ 0.60 — it is not mostly a restatement of the
    scene. Among eligible candidates, choose the largest headroom (ties to the better-balanced class). If none is
    eligible, P1.2.1 runs on the scene task alone, and that is recorded.

### 4b. The extended screen, and the input geometry (added 2026-10-21, before any of its data)

The first screen admitted no candidate. Its full-frame presence tasks turned out to be mostly scene in disguise, and for
a measurable reason: at 224 px the frames are too coarse to see the objects. A BDD frame (1280 × 720) is squashed to 224
× 224, 5.7× narrower and 3.2× shorter. The median traffic light is then 2.4 px wide, the median pedestrian 3.7 px. Even
the largest light in an image is narrower than one 16-px ViT patch in every image. So "traffic light present" was being
read off the intersection, not the light. The gate should not rest on a low-headroom task if a better one exists, so a
second screen runs before P1.2.1.

**Candidates** — chosen to be readable at this resolution or freed of the scene by construction:

- **Weather** — clear / rainy / snowy (overcast, partly cloudy and foggy are left out as ambiguous or rare). A global
    property of the frame, so resolution matters little. It is also a plausible domain feature for in-domain adaptation
    to learn. Caveat: weather is half of the walk's regime key, so the walk orders the stream by it.
- **Cell-balanced presence** — `presence_cell:<category>` for car, truck, pedestrian and traffic light. Equal positives
    and negatives are drawn within every (scene × time-of-day) cell, so scene and time of day carry no information about
    the label. Overlap is then near 0.5 by construction, and the screen measures only signal beyond the scene.

**The rule (fixed now).** As before, but with a headroom floor: a candidate is eligible if its overlap is ≤ 0.60 **and**
its headroom (full-label ceiling − B5 linear) is ≥ **0.10**. Among the eligible, choose the largest headroom. The scene
task is read beside them as the reference, never chosen. If none is eligible, this is a **decision point** for the user
(the options then include an aspect-preserving 224 × 400 input), not an automatic fall-back to scene alone.

**The input geometry.** The squash also distorts the frame: everything is narrowed 1.78×, outside the 3:4–4:3 aspect
range MAE was pretrained on. Both arms see the same squash, so the contrast is internally fair. But only the adapted arm
can *learn* the distorted geometry, so the squash could inflate an adaptation gain. The screen therefore reads B5 twice,
under the squash and under an aspect-preserving **centre crop** (short side to 224, centre square, the frame's sides
dropped). **Rule (fixed now):** if the centre crop raises B5's scene linear **or** few-shot (*k* = 100) read by ≥
**0.03**, the squash is handicapping the baseline, and that is raised with the user before P1.2.1. Otherwise the squash
stays, and the possible inflation is recorded as a caveat on any PASS. The task choice uses the squash run only: under
the crop, presence labels can refer to objects the crop removed.

**Pool fix.** The first ladder's held-out pool kept a fourth scene: 82 parking-lot frames among the first 14,000 train
images clear the 50-frame filter, while val's 49 do not. Its scene rows were therefore a 4-class task, unlike the
canary. The pool now pins the three canary scenes (`data.scenes`), and the ladder is re-read on it. P1.2.1 pins them
too, so its train-side probes and val gate set agree.

### What gets read

| Encoder | Frozen rungs | Few-shot rungs |
| -- | -- | -- |
| **B5** — the off-the-shelf MAE ViT-B/16 | ✓ | ✓ |
| **Random ViT-B/16** — [P1.2.3](index.md)'s floor reference | ✓ | ✓ |
| **The deep wells** `je_o0.0` / `mae_o0.0` | ✓ | ✓ |
| **Drive checkpoints**, walk and IID × 5 seeds × {JE, MAE}, overlap 0 | start, mid-drive, end | end |

From these, three contrasts, each as Δ = encoder − reference with a 95% interval from a bootstrap over seeds and query
images (`cafl4ds/adaptation.py`, new):

- **Pretraining framing** — well − B5, and drive end − B5. Offline warm-up plus the drive, against doing nothing.
- **Deployment framing** — drive end − its frozen well. Continuing to learn, against stopping at deployment.
- **The rung question** — whether the fine-tune rungs agree with the frozen ones, especially on MAE.

None of these is a gate: P1.1's drive is 119 steps and its well trained offline on multiple passes, so neither is the
online adaptation leg (a) asks about. They size the effects P1.2.1 will meet, and test its instruments.

## Handover

*Sequenced plan for a fresh session (state at design time; updated at each pause).*

1. **Engineering.** `scripts/read_adaptation.py` + `cafl4ds/adaptation.py` (ladder, per-image correctness, presence
    labels, bootstrap) with unit tests on the synthetic source; `warmup.freeze_encoder` and `resume_well` in
    `scripts/warm_well.py`. Pre-commit clean.
1. **Few-shot lr** on B5 (part 1). **Done: 3e-5.** Validation balanced accuracy at *k* = 100, mean of three draws: 1e-5
    → 0.616, **3e-5 → 0.643**, 1e-4 → 0.622. Fixed for every fine-tune read from here on.
1. **Head-settle scout** (part 3). **Done.** Heads plateaued with the encoder frozen (MAE 1,430 steps, JE 550; the
    encoder verified bit-identical, its reads constant). Dip over steps 100–500, fresh heads → settled heads, kNN /
    linear: **JE** 0.026 / 0.043 → −0.027 / 0.004 — *mostly a head transient*; **MAE** 0.061 / 0.080 → 0.020 / 0.038 —
    *partly a head transient* (the linear dip is just under half its fresh-head size). The heads-only stage is cheap,
    so P1.2.1's design stands.
1. **Task screen** (part 4). **Done: no candidate eligible.** Overlap with scene + time of day: traffic light 0.71,
    pedestrian 0.68, truck 0.65 (bar ≤ 0.60). Headroom (full-label ceiling − B5 linear): +0.13 / +0.08 / +0.08. P1.2.1
    gates on the scene task alone and reads traffic light as a non-gating secondary — recorded in [P1.2.1](P1.2.1.md).
1. **Ladder reads** over the table above; contrasts; results into this doc, `latest-results/P1.2.0.md`, and the index
    row.

## How to run

All runs as made on the Gaudi node, from the repo root, one worker per card. The full launcher, with the encoder lists
it generates, is promoted as [`artifacts/P1.2.0/run_p120.sh`](artifacts/P1.2.0/run_p120.sh). The key calls:

```bash
TRAIN=/abs/path/to/bdd100k   # BDD train: the held-out pool for the val-trained P1.1 models
POOL="data=bdd bdd_root=$TRAIN data.min_canary_count=50 device=hpu img_size=224 encoder=vit_b16_mae \
 pool.split=train pool.max_images=14000 threads=8"

# 1. The few-shot learning rate, on B5 (the default encoder list is B5 alone):
python scripts/read_adaptation.py $POOL mode=select_lr hydra.run.dir=outputs/p120/lr_select
# 2. The presence-task screen, on B5:
python scripts/read_adaptation.py $POOL mode=screen fewshot.lr=3e-5 hydra.run.dir=outputs/p120/screen
# 3. The head-settle scout, per backbone (JE: drive lr 3e-5; MAE: 1e-4), on P1.1.0's deep diet ($DIET there):
python scripts/warm_well.py $DIET backbone=mae optim.lr=3e-4 warmup.freeze_encoder=true warmup.stop=loss \
  warmup.window=200 warmup.tol=0.002 warmup.min_steps=500 warmup.max_steps=3000 warmup.select_every=100 \
  stream.select_support_per_canary=50 stream.select_query_per_canary=50 warmup.drive_read_per_class=500 \
  well_out=wells/p120/mae_heads.pt
python scripts/warm_well.py $DIET backbone=mae optim.lr=1e-4 resume_well=wells/p120/mae_heads.pt warmup.stop=budget \
  warmup.max_steps=1000 warmup.select_every=25 stream.select_support_per_canary=50 stream.select_query_per_canary=50 \
  warmup.drive_read_per_class=500 well_out=wells/p120/mae_unfrozen.pt
# 4. The ladder, per backbone (encoders_<bb>.yaml lists B5 + random [JE list only], the well, and the walk / IID
#    checkpoints at step 60 and the end, 5 seeds each):
python scripts/read_adaptation.py $POOL 'tasks=[scene,"presence:traffic light","presence:pedestrian","presence:truck"]' \
  backbone=mae fewshot.enabled=true 'fewshot.tasks=[scene]' fewshot.lr=3e-5 '~encoders' \
  encoders_file=outputs/p120/encoders_mae.yaml hydra.run.dir=outputs/p120/ladder/mae
# 5. The analysis (CPU, minutes):
uv run python scripts/analyze_adaptation.py mode=p120 root=outputs/p120
```

The canary-pool read is step 4 with
`$DIET stream.select_support_per_canary=150 stream.select_query_per_canary=150 pool.kind=canary probe_per_class=1000` in
place of `$POOL` and the task list.
