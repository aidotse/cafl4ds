# Reading protocol — degradation vs. benign reorganization `[analysis + new runs]` (P1.1.1)

**What this substudy is.** The second P1.1 sub-study (see the [Phase 1 overview](index.md)). [P1.1.0](P1.1.0.md)
measured how much a healthy drive moves the health instruments, and found one effect that needs explaining. On the
joint-embedding (JE) backbone, the correlated walk compresses the projector and pulls the representation away from the
well, while the labelled canary stays flat. P1.1.1 turns that null into a **decision rule** a monitor can apply to a
single drive, and asks whether JE's compression is degradation or benign reorganization. It also gives the MAE backbone
its first degradation of known size on the deployment substrate, so the rule's power can be measured where Phase 0 found
no label-free reader at all.

**Verdict: both questions are answered.**

| Question | Answer |
| -- | -- |
| Can a monitor call a single drive? | Yes. Healthy drives raise a false alarm on about one drive in ten per panel. On damage of known size, the canary catches a dent of ~6–8 points and misses ~3, on both backbones, on walk and IID alike. That is the ruler P1.3 / P1.4 read degradation with. |
| Is JE's compression collapse, or benign? | Benign. It reverts when the diet mixes, and undoes within 10 IID steps at no accuracy cost. Real collapse, dialled in on the same ViT-B, compresses the projector as much — but also lowers *backbone* RankMe, which the walk does not. |

Two limits come with the answer. A 3-class canary barely notices even heavy collapse, so JE collapse is read on the
projector and backbone RankMe together, not on the canary. And the backbone-RankMe discriminator rests on 3 seeds of one
collapse knob. By-products: MAE's first degradation of known size (P1.1.2's screen), and a lead for P1.4 — at a higher
learning rate the walk itself degrades JE.

## Motivation and framing

A null says how much healthy movement to expect. It does not yet say how to call one excursion. Three priors shape the
rule.

- **Information loss is the arbiter.** The original framing split movement into "benign drift" (non-mean-reverting, no
    performance loss) and "forgetting" (information lost). P1.1.0's data does not fit that split: JE's compression
    *reverts on its own* (below) and costs no accuracy. So the arbiter is whether information is lost, read on the
    labelled canary, and how fast an instrument returns under re-exposure. Mean reversion is evidence, not the
    criterion.
- **Ground truth per backbone.** On MAE the canary is reader *and* arbiter — Phase 0 found no label-free MAE quality
    reader ([P0.5](../latest-results/P0.5.md)). On JE, a 3-class canary can survive substantial rank loss, so whether
    the projector compression is incipient collapse is decided against a **collapse control on the same warm ViT-B**,
    not against Phase 0's 2.0× bar, which was set on a from-scratch tiny ViT.
- **A rank drop can be benign.** Deep-layer rank loss is often task compression that costs nothing in-distribution (the
    tunnel effect, Masarczyk 2023).

**Why MAE is in scope.** The JE effect is the immediate target, but the surgical positive control matters more for MAE.
Phase 0 never had an MAE degradation of known size to test anything against: every natural lever resisted
([P0.3](../latest-results/P0.3.md)). Damaging the real ViT-B MAE well gives one. It yields the MAE canary's power curve
here, and the damaged drives log the full label-free vector, which [P1.1.2](index.md) mines for a label-free MAE reader.
The caveat: artificial damage *screens* readers (one that misses a large dent is useless) but cannot *certify* one,
because it may only detect "weights were scrambled" — the trap P0.5.3 hit. Certification needs a natural MAE failure,
which is P1.3's.

## Methodology

### The single-trajectory rule

A deployed monitor sees one drive, not a seed ensemble. So each instrument is read on its own trajectory against **null
bands** calibrated on the healthy IID drives ([`cafl4ds/reading_protocol.py`](../../../cafl4ds/reading_protocol.py)):

- **Scale.** Drift instruments are read on a log scale (their healthy noise is multiplicative — a seed's drift can jump
    4× for one reading); the rest raw.
- **Residual.** The reading minus the null's seed mean at that checkpoint, signed so positive means "worse than healthy"
    (RankMe and the canary fall, drift rises). Instruments with no known harmful direction are read two-sided.
- **Spread.** A local seed spread per checkpoint, pooled over ±15 neighbouring checkpoints and floored at a quarter of
    the drive-wide spread. It comes from leave-one-out residuals (each seed against the mean of the others), the spread
    a new trajectory meets. A single spread for the whole drive misreads drift, whose healthy spread grows from zero.
- **Smoothing.** The canary is averaged over 5 readings (it jitters by ~0.01–0.02 per reading); the label-free
    instruments are read raw.
- **Threshold.** One threshold per *panel* (below), read off the healthy seeds themselves. Each seed is scored against
    bands fitted on the other seeds, and its maximum *z* — over the whole drive and every instrument in the panel — is
    recorded. A drive's maximum *z* is a maximum over ~120 correlated readings, and maxima follow a Gumbel law; fitting
    its two moments to the seeds' maxima extrapolates to the 95% quantile, which ten seeds cannot reach directly. The
    threshold never sits below the largest healthy maximum, so no calibration seed fires. Sharing one threshold within a
    panel prices in the instruments' correlation (the two drift forms move together) without a Bonferroni split.
- **Panels.** The instruments form two panels — label-free and canary — each held at α = 0.05 over the whole drive. Loss
    and grad norm are left out: on this diet they separate walk from IID mechanically (P1.1.0). RankMe is read
    one-sided, a fall being harm: damage *raises* RankMe (see the pilot below) and already fires the canary and drift,
    so a two-sided RankMe would add false alarms without adding power.
- **Skipped readings.** Readings right after a batch of fewer than 8 images are skipped. Each leg flushes its remainder
    as one short batch (down to 2–3 frames), the IID control copies those sizes, and a tiny update jolts the instruments
    in healthy drives too.
- **Verdict.** `quiet` (nothing fired), `movement` (label-free only), `degradation` (a canary channel fired), the last
    tagged **transient** or **persisting** by whether a canary channel is still over threshold at the drive's end.

The rule is calibrated on 10 healthy IID seeds per backbone (P1.1.0's 0–4 and fresh seeds 5–9). Validation is two-sided.
It must stay quiet out of sample — leave-one-out with bands *and* threshold refitted without the seed, and 5 further
fresh seeds (10–14) — and fire on the controls below.

A first version simulated the threshold from an AR(1)-plus-offset model of the residuals, calibrated on 5 seeds. It ran
low out of sample: drift behaves like a random walk (lag-1 autocorrelation ~0.98), and five seeds underestimate its
late-drive spread (see Findings).

### The controls

All branch from P1.1.0's deep overlap-0 drives. Every damaged arm **resumes** the drive from the leg checkpoint at
**step 65**. That is the start of the long `night·clear` leg, which leaves 54 steps to watch the dent evolve. Each arm
runs on **both** the IID control and the walk, 3 seeds each ([`cafl4ds/branch.py`](../../../cafl4ds/branch.py)). A
resumed drive restarts AdamW (the checkpoint stores the model, not the optimizer), so each arm is compared with a
**dose-0 twin** resumed the same way. The damage draws from its own seeded generator, so a dose and its twin see
identical augmentation and masking.

- **Surgical damage**, on both backbones: Gaussian noise on every weight matrix of all 12 encoder blocks at σ ∈ {0.3,
    0.5, 0.75, 1.0} × each tensor's own SD, and re-initialization of the top 4 or all 12 blocks.
- **Warm collapse dial**, on JE: P0.2.5's loss-blend knob (`collapse_alpha`; α = 1 is P0.2's forced-collapse objective)
    on the same warm ViT-B. At the drive's lr (3e-5) it barely moved the model in 54 steps, so the dial runs at lr 1e-4.
    The sweep is α ∈ {0, 0.6, 1.0} on the IID branch and α ∈ {0, 1.0} on the walk branch, 3 seeds, each read against its
    α = 0 twin *at the same lr*. Seed-0 extras: α = 0.3, a full 119-step drive from the well (α ∈ {0, 1}), and P0.2.5's
    other knob (stop-gradient off, `stopgrad_beta = 0`).
- **Recovery pass**: 60 steps of the well's stationary pool (disjoint from the drive), from the end of each P1.1.0
    drive, seeds 0–2. Does the walk's compression undo under IID data? The IID drive's end is the control, since the
    pass restarts the optimizer too.

The dose ladder came from a probe-only **pilot**: each dose applied to the well and read once, with no training
([`scripts/dose_pilot.py`](../../../scripts/dose_pilot.py)).

## Findings

### The rule's false-alarm rate is ≲10% per panel

Out-of-sample false alarms, per panel (any instrument firing anywhere in the drive):

| Panel | Threshold | Leave-one-out, 10 seeds | Fresh seeds 10–14 | Fresh seeds' largest *z* |
| -- | -- | -- | -- | -- |
| JE label-free | 4.61 | 1 / 10 | 1 / 5 | 2.97, 2.85, **5.39**, 2.42, 2.50 |
| JE canary | 3.73 | 1 / 10 | 0 / 5 | 2.86, 3.21, 3.24, 2.23, 3.10 |
| MAE label-free | 4.41 | 2 / 10 | 0 / 5 | 3.09, 3.53, 3.85, 2.97, 2.73 |
| MAE canary | 4.60 | 1 / 10 | 0 / 5 | 3.24, 2.43, 2.19, 3.49, 2.79 |

Pooled over the 15 out-of-sample trials, that is 1–2 alarms per panel, or roughly 7–13%. Fifteen trials cannot pin a 5%
rate, so the honest claim is "≲10%". The simulated threshold it replaces ran at 10–37% on the same check.

- **The leave-one-out alarms are the tail itself.** Each is a single outlier seed. Leaving it out lowers the threshold,
    so it fires. That is inherent to reading a tail off ten seeds.
- **The one fresh alarm is a real late excursion, not a short-batch artefact.** JE seed 12's projector uniformity sits
    at −1.73 at steps 110–114, against a null mean of −1.58 (null range −1.63 to −1.51). Those readings follow full
    batches. The healthy JE maxima cluster in the same late stretch (steps 110–111). The canary on seed 12 is normal.
- **Why the first version failed.** It simulated the threshold from an AR(1)-plus-offset model and calibrated on 5
    seeds. Drift is closer to a random walk (lag-1 autocorrelation 0.976–0.983 for JE `cka_drift` / `cosine_drift`).
    Five seeds underestimated its late-drive spread, so the JE label-free panel fired on all 5 fresh seeds 5–9.

### Read on the walk

- **JE: the label-free panel fires on every walk seed.** Projector RankMe reaches *z* 8–13 and projector uniformity
    19–27. The correlation effect P1.1.0 found is large on a single trajectory, not only in a 5-vs-5 contrast.
- **JE: the canary fires transiently on 3 of 5 walk seeds**, on a time-of-day stratum the walk is *not* streaming. Seeds
    0 and 2 fire on night accuracy during the daytime legs (from steps 9–30, *z* 4.1–4.6, 4–12% of readings). Seed 3
    fires on dawn/dusk kNN during the night legs (from step 88, *z* 4.6). No seed is still over threshold at the drive's
    end. The walk recovers, and overtakes IID on the night stratum once it reaches the night legs. That is a recoverable
    regime-specialization dip, the "genuine but recoverable" case [P0.3.5](../phase0/P0.3.5.md) separated.
- **MAE: label-free movement only.** Four of 5 seeds fire one instrument each (drift or uniformity, ≤2% of readings, *z*
    4.5–5.3); one seed is quiet. The canary never fires.

### JE's compression reverts — with the diet, and at once under IID data

The walk-minus-IID gap in projector RankMe, averaged over the last 8 readings of each time-of-day block, per seed:

| Block end | Seed 0 | 1 | 2 | 3 | 4 |
| -- | -- | -- | -- | -- | -- |
| daytime (step 55) | −3.2 | −3.6 | −4.0 | −2.7 | −0.5 |
| dawn/dusk (step 63) | −1.6 | −1.2 | −1.7 | −1.8 | +1.7 |
| night (end) | −3.5 | −0.5 | −6.2 | −1.0 | +0.1 |

The dawn/dusk block is eight short, mixed legs. Across it the gap closes in every seed, and it reopens on the long
night·clear leg. Projector uniformity moves the same way in all 5 seeds. A correlation with the trailing regime count
over the whole drive is weak (|ρ| ≤ 0.3). So the reversion is an event at the mixed stretch, not a smooth dose–response.

The recovery pass makes the same point directly. Seed means at steps 0 / 10 / 50 of 60 IID well-pool steps (MAE: start →
end):

| From the end of… | `rankme_proj` | `uniformity_proj` | `cka_drift` | backbone RankMe | canary linear / kNN |
| -- | -- | -- | -- | -- | -- |
| JE walk | 9.55 → 12.16 → 11.76 | −1.18 → −1.64 → −1.63 | 0.114 → 0.057 → 0.044 | 20.5 → 18.1 → 19.5 | 0.622 / 0.523 → 0.611 / 0.530 |
| JE IID (control) | 10.34 → 10.87 → 10.77 | −1.57 → −1.57 → −1.56 | 0.012 → 0.007 → 0.010 | 22.1 → 22.0 → 21.7 | 0.596 / 0.531 → 0.585 / 0.514 |
| MAE walk | — | — | 0.029 → 0.002 | 32.1 → 33.0 | 0.557 / 0.453 → 0.555 / 0.472 |
| MAE IID | — | — | 0.020 → 0.003 | 30.6 → 32.3 | flat |

JE's walk compression undoes within ~10 IID steps, and the canary does not move. The control rules out the optimizer
restart: a healthy model moves projector RankMe by ≲ +0.8 and uniformity not at all. The upshot is that the projector
adapts to the regime it currently sees and lets go as soon as the diet mixes again. That is benign specialization, not
lost information.

What the tables say:

- **The canary calls a linear dent of ~6–8 points or more, on both backbones; a ~3-point dent is missed.** This matches
    P1.1.0's minimum detectable gap (0.024–0.045 pooled), now validated against damage of known size. A large dent fires
    at the first reading after the damage.
- **Walk and IID read the same.** The same dose gives almost the same dent and the same time-to-fire on both orders.
    Correlation neither masks nor amplifies the damage.
- **No healing within the drive.** The dent at the end is about the immediate dent, on both backbones, over 54 steps.
    This is consistent with Phase 0: recovery needs re-exposure to the lost data, and a drive moving on to new regimes
    does not supply it.
- **MAE's dent is about half JE's at the same dose** (σ1.0: −11 vs −17 points linear).
- **Re-initializing the top 4 blocks does nothing measurable**; only re-initializing all 12 bites. The fresh blocks add
    little to the residual stream, so the lower blocks carry the representation through.
- **On the label-free side, branches must be read against their twin.** The resumed branch restarts AdamW, which jolts
    drift. So drift fires on dose-0 branches too (on every MAE dose-0 branch, and on the JE walk dose-0 branch).
    [P1.1.3](P1.1.3.md) later sized this: on MAE the jolt lasts 1–2 readings; on JE there is none. The JE walk twin's
    fires come late (steps 84–117), from the walk's own drift: the original drives fire there too on 2 of 3 seeds, and
    the twin never departs from its original by more than ~2 null SDs. Backbone RankMe fires mainly at the largest
    doses: σ1.0 and re-init 12 on both backbones, and MAE re-init 4. It also fires on single seeds of JE walk σ0.75 and
    dose 0, and MAE walk σ0.75. The per-signal label-free dents against the twin are in the report
    (`branches[...]["dent_vs_dose0"]`). They are P1.1.2's input for the MAE reader screen.

### Warm collapse dial — collapse costs the canary little

At the drive's lr (3e-5), even the full collapse objective barely moved the warm ViT-B in 54 steps: projector RankMe
11.05 → 10.64, against a twin at 11.10 → 11.47. At lr 1e-4 it bites. Change against the α = 0 twin at lr 1e-4, mean over
the branch / at the end, seeds 0–2:

| Arm | `rankme_proj` | backbone RankMe | `uniformity_proj` | `cka_drift_proj` | linear | kNN | night kNN |
| -- | -- | -- | -- | -- | -- | -- | -- |
| IID, α = 0.6 | −0.4 / −0.4 | −3.4 / −3.7 | +0.17 / +0.13 | +0.06 / +0.04 | +0.008 / +0.013 | +0.001 / +0.001 | −0.006 / −0.000 |
| IID, α = 1.0 | −2.1 / −3.1 | −6.1 / −8.6 | +0.43 / +0.32 | +0.14 / +0.20 | +0.009 / −0.016 | −0.005 / −0.035 | −0.018 / −0.020 |
| walk, α = 1.0 | −0.1 / −0.9 | +1.5 / +1.2 | −0.02 / +0.04 | −0.05 / −0.04 | +0.005 / +0.008 | +0.016 / +0.015 | +0.020 / +0.020 |

In absolute terms, IID α = 1.0 takes projector RankMe from 10.6 to 6.9 over the last 8 readings (twin 11.1), and
backbone RankMe from 18.8 to 11.6 (twin 20.6). The full 119-step drive from the well (seed 0) goes further. Over its
last 10 readings, projector RankMe is 4.7 against the twin's 12.5 (**2.7× lower**) and backbone RankMe 10.7 against 20.3
(1.9×). Even so, the canary loses only 2–5 points over the second half (linear −2.6, night linear −3.3, night kNN −5.1).

- **A collapse of 2× or more on the projector costs a 3-class canary only a few points.** The prior that the canary
    survives substantial rank loss holds on the warm ViT-B. So the dial, not the canary, is JE's collapse reference.
- **The dial is graded but steep.** α = 0.6 lowers only backbone RankMe (−3.7); α = 1.0 compresses both surfaces. (α =
    0.3 at seed 0 looked like α = 0.6.)
- **On the walk, α = 1.0 adds nothing over its twin.** At lr 1e-4 the walk twin has already lost most of what collapse
    would take (next section).
- **The other knob is weaker.** Stop-gradient off (seed 0) moves projector RankMe noisily, ending −5 against the twin,
    and costs 1–6 canary points. Backbone RankMe does not fall.
- **The rule calls collapse only through the twin.** The bands were calibrated at lr 3e-5, so at lr 1e-4 even the α = 0
    twin fires (projector uniformity, backbone RankMe, transient canary slices). Dial arms are read only against their
    twin.

### Projector compression is not collapse: backbone RankMe tells them apart

Collapse and the walk's compression look alike on the projector. Forced collapse in 54 steps takes projector RankMe to
~6.9. The walk takes it to ~7–8.4 (the lr-3e-5 dose-0 walk branch: 10.9 → 8.4). They part on the backbone:

| Arm (54-step branch, seeds 0–2) | `rankme_proj` | backbone RankMe | canary linear | after 10 IID steps |
| -- | -- | -- | -- | -- |
| walk, lr 3e-5 | 10.9 → 8.4 | 19.6 → 19.1 (flat) | 0.615 → 0.600 | projector back to healthy |
| IID collapse α = 1, lr 1e-4 | 10.6 → 6.9 | 18.8 → 11.6 (−40%) | 0.585 → 0.571 | — |

Under the walk, backbone RankMe stays flat and the compression undoes at once. Under collapse, backbone RankMe falls by
40%. So projector RankMe alone cannot call collapse on this backbone; it should be read together with backbone RankMe.
This is a **candidate discriminator** on 3 seeds of one knob. The stop-gradient knob (1 seed) did not lower backbone
RankMe, so it is not yet a general rule.

### A higher learning rate turns the walk harmful

The α = 0 twins at lr 1e-4 against the same seeds' dose-0 branches at lr 3e-5 (mean of the last 8 readings, seeds 0–2):

| Order | linear | kNN | night linear | daytime linear | backbone RankMe |
| -- | -- | -- | -- | -- | -- |
| IID | −0.030 | −0.004 | −0.021 | −0.052 | −1.0 |
| walk | **−0.064** | −0.028 | **−0.073** | **−0.079** | **−6.6** |

At lr 1e-4 the walk costs twice the canary accuracy IID does. Its backbone RankMe falls from 20.5 to 12.6, and the
canary fires and persists on all 3 seeds. So the correlated diet becomes a natural, label-visible JE degradation once
the step size is large enough. It comes with the same backbone-RankMe fall as forced collapse. One caveat: these
branches also change lr at step 65, mid-drive. This is an unplanned finding, and possibly the natural JE failure P1.4
needs.

*Per seed ([P1.1.3](P1.1.3.md)):* the "twice" is a seed-mean statement. The walk's excess loss over IID, on the same
window, is −2.0, −7.7 and +0.1 points on seeds 0–2. On seed 2 the lr-1e-4 IID arm loses as much as the walk. So the
higher lr harms JE on every seed, but the walk-specific part rests on one.

### Handover to P1.1.2, P1.3 and P1.4

- **P1.1.2 (MAE reader search):** the damage branches log the full label-free vector, and the dents against the twin are
    in the report. The MAE screen bar is the canary's: about 6–8 points.
- **P1.1.2 / P1.4 (JE collapse):** read projector RankMe together with backbone RankMe. Test the candidate on the
    stop-gradient knob with more seeds before relying on it. Per-block lenses can show where the compression lives.
- **P1.4:** the lr-1e-4 walk is a candidate natural JE degradation (−6 to −8 canary points, persisting, with backbone
    RankMe falling). Its walk-specific excess over IID is clear on 1 of 3 seeds ([P1.1.3](P1.1.3.md)). It needs a clean
    design: an lr set from the start of the drive, not switched mid-drive. It also bears on P1.3's learning-rate lever.
- **The rule's level:** ≲10% per panel out of sample. A tighter claim needs more healthy seeds, not a better model.

## Code validity

- `cafl4ds/branch.py` — resume, damage and recovery, unit-tested
    ([`tests/unit/test_branch.py`](../../../tests/unit/test_branch.py)). A resumed stream is the original drive's tail,
    batch for batch. Dose 0 leaves the encoder bit-identical. Damage touches only the chosen blocks, is seeded, and
    leaves the global RNG where it was. The recovery pass draws only well-pool frames.
- The deploy harness gains `resume.*`, `damage.*`, `recovery_steps` and `checkpoint_legs=final`, exercised end to end on
    the synthetic source ([`tests/unit/test_scripts_e2e.py`](../../../tests/unit/test_scripts_e2e.py)). A branch records
    the canary just before and after the damage in its report (`config.branch`).
- `cafl4ds/reading_protocol.py` — unit-tested
    ([`tests/unit/test_reading_protocol.py`](../../../tests/unit/test_reading_protocol.py)). It holds its false-alarm
    level on fresh simulated nulls (raw, smoothed, AR(1), and random walks with per-seed offsets calibrated on 10 seeds
    — the case the simulated threshold failed), at the level of a whole panel. It fires at the onset of a harmful shift
    and not on a harmless one, catches a collapsed seed leave-one-out, and skips blanked readings.
- The deploy harness now decodes BDD once per seed ensemble rather than per seed (a seeded synthetic source is still
    rebuilt per seed).

## Artifacts

[`artifacts/P1.1.1/`](artifacts/P1.1.1/):

- [`reading_report.json`](artifacts/P1.1.1/reading_report.json) — the full analysis, per backbone. `rules` / `panels`
    hold each panel's threshold, its leave-one-out and fresh-seed false-alarm rates, and the calibration seeds. `walk`
    and `reversion` hold the per-seed calls and verdicts, and the block-end gaps. `branches` holds every damaged arm's
    calls, its damage record, the immediate dent and `dent_vs_dose0`. `dial` (JE) holds calls and `dent_vs_alpha0`;
    `recovery` holds seed-mean traces.
- `heldout/`, `heldout2/`, `branch/`, `dial/`, `recover/` — one directory per arm, each with its resolved `config.yaml`,
    `manifest.json` and full corpus (`health.csv`, plus `segments.json`). Branches add `branch.json`: the per-seed
    damage, relative weight change, and instruments before and after the damage.
- `pilot/{je,mae}.json` — the dose pilot (each dose's damage, relative weight change and full instrument read), with the
    resolved configs.
- `queue.sh`, `queue2.sh`, `queue3.sh`, `queue4.sh` — the run queues, as launched.

Raw runs sit in the gitignored `outputs/p111/`, on this node's local disk. Model checkpoints — what a weight-level lens
(P1.1.2's per-block CKA, intrinsic dimension) can read — exist only where listed. Each is a full method, ~330 MB:

- **Healthy and walk drives, every leg:** P1.1.0's overlap-0 drives, under
    `outputs/p110_deep/warm/{je,mae}_o0.0_{walk,iid}/checkpoints/s{0..4}/` — `step<s>.pt` at each of the 17 leg
    boundaries plus `final.pt`, with an `index.json`.
- **Damage branches, end state only:** `outputs/p111/branch/<bb>_<order>_<dose>/checkpoints/s{0,1,2}/final.pt` (27 GB).
    The state right after the damage is not saved, but it is reproducible: load the step-65 leg checkpoint and apply the
    seeded damage (`branch.damage_top_blocks`, as `scripts/dose_pilot.py` does).
- **No checkpoints:** the fresh healthy seeds (`heldout{,2}/`), the collapse dial (`dial/`) and the recovery passes
    (`recover/`) — their corpora hold the scalar instruments only. A weight-level read on them needs a re-run with
    `checkpoint_legs=true`.

## How to run

On the Gaudi node, from the repo root. On a CPU/GPU box, drop the launcher and use `uv run python ... device=cpu|cuda`.
The diet is P1.1.0's deep diet (`$DIET` below), and every arm needs the P1.1.0 deep wells and leg checkpoints.

```bash
BDD=/abs/path/to/bdd
DIET="data=bdd data.split=val data.min_canary_count=50 bdd_root=$BDD device=hpu img_size=224 encoder=vit_b16_mae \
 stream.support_per_canary=45 stream.query_per_canary=45 stream.stratify_canary=true stream.well_fraction=0.5 \
 stream.select_support_per_canary=150 stream.select_query_per_canary=150 stream.well_overlap=0.0 \
 gate_arms=false eval_every=1 study=P1.1.1"
run() { card=$1; shift; ./scripts/run_gaudi_dev.sh -m $BDD -m /mnt/cifar100 gaudi-env-cafl4ds:latest $card "$@"; }
CK="outputs/p110_deep/warm/je_o0.0_iid/checkpoints/s{seed}/step00065.pt"

# The dose pilot (minutes): each dose read on the well, no training.
run 0 python scripts/dose_pilot.py $DIET backbone=je well=wells/p110_deep/je_o0.0.pt \
  'doses=[reinit:4,reinit:12,noise:12:0.3,noise:12:0.5,noise:12:0.75,noise:12:1.0]' hydra.run.dir=outputs/p111/pilot/je

# Fresh healthy seeds (the rule's calibration 5-9, and its check 10-14).
run 0 python scripts/run_deploy_harness.py $DIET backbone=je optim.lr=3e-5 stream.order=iid \
  well=wells/p110_deep/je_o0.0.pt 'seeds=[10,11,12,13,14]' hydra.run.dir=outputs/p111/heldout2/je_iid

# One damaged branch: resume the IID drive at step 65, noise all 12 blocks at sigma 0.5, 3 seeds.
run 0 python scripts/run_deploy_harness.py $DIET backbone=je optim.lr=3e-5 stream.order=iid \
  well=wells/p110_deep/je_o0.0.pt "resume.checkpoint='$CK'" resume.step=65 checkpoint_legs=final \
  damage.mode=noise damage.k=12 damage.scale=0.5 'seeds=[0,1,2]' hydra.run.dir=outputs/p111/branch/je_iid_noise0.5

# One collapse-dial arm: the same branch at lr 1e-4 with the full collapse objective (alpha 0 = its twin).
run 1 python scripts/run_deploy_harness.py $DIET backbone=je optim.lr=1e-4 stream.order=iid \
  well=wells/p110_deep/je_o0.0.pt "resume.checkpoint='$CK'" resume.step=65 '+ssl.collapse_alpha=1.0' \
  'seeds=[0,1,2]' hydra.run.dir=outputs/p111/dial/je_iid_alpha1.0_lr1e-4_s012

# The analysis (CPU, ~15 s) — writes outputs/p111/reading_report.json.
uv run python scripts/analyze_reading.py
```

The full set of arms is in the queue scripts under [`artifacts/P1.1.1/`](artifacts/P1.1.1/). Each queue runs one worker
per card and skips any arm whose corpus already exists.
