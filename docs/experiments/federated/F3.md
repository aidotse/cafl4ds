# F3 — Does from-scratch federated MAE learn on CIFAR-100, and do the aggregation methods help?

[F2](F2.md) could not see a non-IID effect because its federated phase re-trained on data the warm start had already
learned. F3 steps back to the prior question: **does federated MAE training on CIFAR-100 learn at all**, from scratch
and from a warm start, and how far does it fall short of centralized training? Once it does learn, F3 asks whether the
alternative aggregation methods (FedAdam, FedProx) improve on FedAvg under Dirichlet label skew.

All results are seed 0 only.

## Setup

**Model.** The F2 ViT-Tiny (`patch_size=4`, `embed_dim=192`, `depth=12`, `num_heads=3`, `mlp_ratio=4`) with the F2 MAE
decoder (`decoder_dim=192`, `decoder_depth=4`, `decoder_heads=3`, `decoder_mlp_ratio=4`), `mask_ratio=0.75`,
`norm_pix_loss=true`. CIFAR-100 at 32px, batch 128, AdamW at `lr=5e-4`, gradient clip 1.0.

**Federation.** 4 clients, `steps_per_round=5`, `stream=iid` (shuffled order *within* each client, so only the partition
varies). Partition `iid` or `dirichlet` with `α=0.1`. The global hold-out reserves 101 images per class before
partitioning, which leaves 399 per class (about 10k images per client).

**Passes.** Each client streams its shard once (`client_epochs=1`) or five times (`client_epochs=5`). A pass spans about
16 rounds, so extra passes add rounds, not local steps between averages. Five passes is about 78 rounds under IID and 84
under Dirichlet; the larger Dirichlet shard runs longer.

**Warm start.** `pretrain.py`, 40 epochs over the same CIFAR-100 training images. Pretrained and federated data
therefore overlap fully, as in F2.

**Readouts.**

- *Per round:* the health monitor on the global hold-out (probe support 40 and query 50 per class). Label-free geometry,
    drift, kNN and linear probes, and per-client divergence.
- *Once, before and after training:* the **final evaluation** (`final_eval.enabled=true`). kNN (k=20) and linear probes
    are fitted on the full 50k-image training split and scored on the official 10k CIFAR-100 test split, which nothing
    else in a run touches. The same probes score the starting and the final model, so `gain = final − start` is what
    training added.

## Findings

### Centralized MAE learns from scratch, but one pass is far too little

Final evaluation, test-split accuracy:

| Run | kNN | Linear probe |
| -- | -- | -- |
| Centralized, 40 epochs, scratch | 9.7% → 25.9% (+16.2) | 19.3% → 38.7% (+19.4) |
| Centralized, 1 pass, scratch | 9.7% → 9.9% (+0.2) | 19.3% → 19.0% (−0.3) |
| Centralized, 1 pass, pretrained | 25.7% → 25.6% (−0.2) | 38.4% → 38.4% (+0.1) |

CIFAR-100 is big enough to learn from: forty epochs gain about 16–19 points. One pass (313 steps) does not.

The reason is an **early dip**. A random ViT already linear-probes at about 19%, because random features carry some
information. MAE's first updates reorganize those features before improving them. On the per-round probe, the one-pass
run falls from 0.101 to 0.080 by step 50 and only climbs back to 0.122 by step 312. It ends roughly where it began.

The pretrained run does not move. That is F2's overlap: it re-trains on images the checkpoint already learned. As a
consistency check, its starting score (25.7% / 38.4%) matches the 40-epoch run's final score (25.9% / 38.7%), which is
the same training recipe.

### One federated pass ends *below* the random start; five passes learn

| Run | kNN | Linear probe |
| -- | -- | -- |
| FedAvg, 1 pass, scratch, IID | 9.7% → 7.8% (−1.9) | 19.4% → 12.9% (−6.5) |
| FedAvg, 1 pass, scratch, Dirichlet | 9.7% → 7.3% (−2.3) | 19.4% → 13.0% (−6.4) |
| FedAvg, 1 pass, pretrained, IID / Dirichlet | ≈ no change | +0.3 / +0.3 |
| **FedAvg, 5 passes, scratch, IID** | 9.7% → 12.4% (+2.8) | 19.4% → 23.3% (+3.9) |
| **FedAvg, 5 passes, scratch, Dirichlet** | 9.7% → 12.9% (+3.2) | 19.4% → 24.8% (+5.5) |

With one pass, federated training stops inside the dip. Each client takes only about 78 local steps, and every round
averages four clients' steps into one global update. So FedAvg makes roughly a quarter of the centralized progress per
pass, at the same learning rate. Its RankMe ends near 4, against 9 for the centralized pass.

With five passes the dip lasts about one pass (the per-round linear probe recovers by round 24). After that the model
learns steadily and is **still improving at the end**: RankMe reaches 14–16, and the loss and probes are still moving.
Five passes are not a ceiling.

### No non-IID penalty at α=0.1

The Dirichlet run scores slightly *higher* than IID (+5.5 vs. +3.9 linear). Most of that gap is the six extra rounds the
larger Dirichlet shard provides, at a point where the model is still improving. At equal rounds the per-round linear
probe is nearly identical (0.138 vs. 0.143 at round 72).

The divergence metrics agree. Clients diverge more under Dirichlet only in round 0 (`cross_client_cka_max` 0.097 vs.
0.011). From there on the two partitions look alike, mostly between 0.01 and 0.04.

**Interpretation.** At this setting the non-IID condition is not strong enough to matter. Label skew over 100 classes
reaches a label-free objective like MAE only through the feature distribution it induces, and each client still sees
broadly similar images. This repeats F2's reading, now in a regime where training does real work. It is "no penalty
*detected* at α=0.1", not "non-IID does not matter".

### Plain FedAvg beats every alternative aggregation method

Five passes, scratch, Dirichlet α=0.1:

| Method | kNN gain | Linear gain | Curves |
| -- | -- | -- | -- |
| **FedAvg** | **+3.2** | **+5.5** | learns steadily |
| FedProx μ=0.1 | +1.6 | +2.6 | learns, more slowly |
| FedProx μ=0.01 | — | — | stopped at round 39; tracks FedAvg closely up to there |
| FedAdam lr=3e-4 | −1.9 | −4.7 | no collapse; stalls (RankMe ≈ 8) |
| FedAdam lr=1e-3 | −2.7 | −5.5 | no collapse; stalls (RankMe ≈ 6 from round 56) |
| FedAdam lr=1e-2 | −6.3 | −6.2 | **collapses** (RankMe → 1.03, uniformity → 0) |

**Why.** FedProx and FedAdam exist to correct client drift, and the previous finding shows there is little drift at
α=0.1. With nothing to correct, they only add their side effects.

- **FedProx** pulls each client back towards the broadcast model, which here mostly slows useful learning. The weak pull
    (μ=0.01) tracks FedAvg; the stronger one (μ=0.1) falls behind. The clients use AdamW, which rescales each weight's
    gradient. For weights the MAE loss barely touches, the proximal term may dominate and be scaled up, so the effective
    pull is likely stronger than μ suggests. This is not verified.
- **FedAdam's** step size is poorly matched at all three learning rates. At `lr=1e-2` (with `tau=1e-3`), weights the
    clients barely moved are stepped up to about 10× their actual change, and server momentum keeps pushing; MAE
    collapses within the first rounds. At `1e-3` and `3e-4` it does not collapse but stalls. A plausible cause is
    `beta_2=0.99`: its memory of about 100 rounds exceeds the 84-round run, so the large updates of the early
    reorganization (client drift about 0.65 at round 4) keep later steps small. A fair FedAdam test would also tune
    `tau` and `beta_2`.

The label-free monitors caught the FedAdam collapse at once: RankMe fell to 1 and uniformity to 0 within the first
rounds.

## Caveats

- **One seed.** FedAvg's lead over FedProx μ=0.1 (about 3 points) is consistent along the whole curve and probably real,
    but it needs seeds 1–2. The IID-vs-Dirichlet gap is within what one seed resolves.
- **FedAdam results describe these hyperparameters**, not the method.
- **The centralized 5-pass reference was not run**, so the cost of federation at equal passes is not measured. The
    40-epoch run's per-round probe reads about 0.20 after five epochs, against 0.15–0.16 for five-pass FedAvg, which
    suggests a sizeable gap.
- **Drift values carry a reference offset when `track_client_health=true`.** The monitor takes its drift reference from
    the first model it measures, which with per-client health is client 0 after round 0, not the global model. Drift is
    comparable within a run and across runs with the same setting. All five-pass runs here had it on.

## How to run

```bash
ENC="encoder.patch_size=4 encoder.embed_dim=192 encoder.depth=12 encoder.num_heads=3 encoder.mlp_ratio=4"
MAE="ssl=mae ssl.decoder_dim=192 ssl.decoder_depth=4 ssl.decoder_heads=3 ssl.decoder_mlp_ratio=4"
DATA="data=cifar100 data_root=/path/to/data img_size=32 max_per_class=null max_train_per_class=null"
PROBE="support_per_class=40 query_per_class=50 era_eval_per_class=10"
SPROBE="stream.support_per_class=40 stream.query_per_class=50 stream.era_eval_per_class=10"
TRAIN="batch_size=128 optim.lr=5e-4 final_eval.enabled=true device=cuda"
CKPT="pretrain_dir=checkpoints/mae_cifar100_40ep"

# Warm start (40 epochs)
uv run python scripts/pretrain.py $MAE $ENC $DATA $SPROBE batch_size=128 optim.lr=5e-4 epochs=40 $CKPT device=cuda

# Centralized: 40 epochs, then one pass from scratch / pretrained
uv run python scripts/run_loop.py $MAE $ENC $DATA $SPROBE $TRAIN stream=iid init=from_scratch +loop.epochs=40 eval_every=313
uv run python scripts/run_loop.py -m $MAE $ENC $DATA $SPROBE $TRAIN stream=iid $CKPT init=from_scratch,pretrained eval_every=25

# FedAvg, 1 or 5 passes, IID vs Dirichlet
uv run python scripts/run_federated.py -m $MAE $ENC $DATA $PROBE $TRAIN $CKPT stream=iid num_clients=4 \
  steps_per_round=5 track_client_health=true strategy=fedavg init=from_scratch client_epochs=5 \
  partition.scheme=iid,dirichlet partition.alpha=0.1 seed=0

# Aggregation methods (5 passes, Dirichlet)
FLB="$MAE $ENC $DATA $PROBE $TRAIN stream=iid num_clients=4 steps_per_round=5 init=from_scratch \
  client_epochs=5 track_client_health=true partition.scheme=dirichlet partition.alpha=0.1 seed=0"
uv run python scripts/run_federated.py -m $FLB strategy=fedadam strategy.server_optimizer.lr=1e-2,1e-3,3e-4
uv run python scripts/run_federated.py -m $FLB strategy=fedprox strategy.proximal_mu=0.01,0.1

# Health plots per run directory
uv run --with matplotlib python scripts/plot_federated_health.py <run_dir>
```

## Open follow-ups

- **A non-IID setting strong enough to matter.** Sharper label skew (`α=0.01`), per-client pixel transforms (feature
    skew), or BDD100K partitioned by driving condition. Only there can the aggregation methods be expected to help.
- **The centralized 5-pass reference**, to measure the cost of federation at equal passes.
- **Seeds 1–2** for the FedAvg / FedProx μ=0.1 comparison.
- **FedProx μ=0.01** to completion (expected close to FedAvg).
- **A fair FedAdam test**, tuning `tau` and `beta_2` alongside `lr`.
- **More passes** (e.g. 10): five-pass runs are still improving at the end.
- **Fix the drift reference** for `track_client_health=true` (give per-client readings their own monitor).
