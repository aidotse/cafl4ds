# Positive control — the batch-size probe (P0.3.3)

[P0.3.2](P0.3.2.md) showed the toy STL-10 vehicles/animals corner hosts **no robust forgetting event**: with precise
(200/200) probes the PC Backward-Transfer centres at +0.02 (task A flat, no crater) and the smoking gun is **R11 ≈
0.56** — task B (animals) barely learns above its four-way floor, so the representation never respecialises enough to
overwrite task A. P0.3.3 is the last attempt to induce forgetting *at toy scale* before escalating the dataset: it tests
whether a **smaller training batch** — the one untried mechanism lever — supplies the missing respecialisation pressure.

## Hypothesis

At `batch_size=128` the ~1,500-image task is nearly full-batch (~12–13 steps/epoch), so phase B takes few, heavily
averaged gradient steps. A smaller batch changes forgetting through two channels at once (epochs held at 300/300):

- **More B-only steps** — halving the batch doubles steps/epoch, i.e. more respecialisation pressure. (P0.3.1 already
    tripled B-steps *via epochs* and the crater stayed flat, so this channel is likely near-exhausted — but smaller
    batch also brings the second channel.)
- **More gradient noise / sharper minima** — near-full-batch finds flatter, more transferable minima (Keskar et al.
    2016); a smaller, noisier batch specialises harder to task B, which could both raise R11 and erode task A.

The concrete prediction: a smaller batch lifts R11 (task B finally learns) and drives PC BWT robustly negative.

## Methodology

Single-axis change from the [P0.3.2](P0.3.2.md) 200/200 baseline (test split, precise probes): only `batch_size` varies,
over **{32, 64}** vs the 128 baseline, **N=5 seeds each** (10 runs). Everything else identical — encoder 256/8 (heads
8), MAE decoder 128/4/4, `img_size=64`, epochs 300/300, linear probe 200/200, vehicles/animals split. The read is the
same as P0.3.2: per-seed PC BWT + R11, and fire-count against the −0.05 threshold, compared to the batch-128 baseline
(0/5 fire, PC BWT centre +0.02, R11 ≈ 0.56).

## Results

| batch | PC BWT min / med / max | fire (≤ −0.05) | R11 med (task B) | learnedA med |
| -- | -- | -- | -- | -- |
| **128** (P0.3.2 baseline) | −0.001 / +0.026 / +0.026 | 0/5 | 0.562 | +0.088 |
| **64** | +0.013 / +0.016 / +0.021 | 0/5 | 0.591 | +0.090 |
| **32** | −0.041 / −0.004 / +0.019 | 0/5 | 0.546 | +0.094 |

Neither batch size produces a robust fire. `batch_size=64` is *uniformly positive* (no forgetting at all).
`batch_size=32` nudges the median just negative (−0.004) and its best single seed reaches −0.041 — still short of −0.05,
and a lone outlier (the other four sit near 0). Crucially **R11 stays ~0.55–0.59 across all three batch sizes**: task B
never learns appreciably above its floor regardless of batch, so the respecialisation pressure the hypothesis needed
never appears. Backbone `cka_drift` is correspondingly tied (PC ≈ healthy, ~0.04–0.05 both arms) — no forgetting to
detect.

## Findings

- **Batch size is not the missing lever.** Both channels (more steps, more noise) were exercised and neither induced
    reproducible forgetting; the tiny bs32 nudge is within seed noise, not a signal.
- **The bottleneck is upstream: task B is unlearnable-to-overwriting under MAE at this scale**, not under-trained by too
    few steps. R11 is invariant to batch size, which rules out step-count/optimisation as the cause and confirms
    P0.3.2's diagnosis — MAE's reconstruction objective on toy STL-10 simply does not build a task-B-discriminative
    representation strong enough to erode task A.
- **Toy STL-10 is exhausted as a forgetting vehicle.** Across P0.3.1 (capacity, erosion), P0.3.2 (seeds, probe size) and
    P0.3.3 (batch size), no knob produces a robust two-sided fire. Calibration escalates to CIFAR-100
    ([P0.3.4](P0.3.4.md)), the canonical catastrophic-forgetting benchmark.

## How to run

Same harness/config as [P0.3.2](P0.3.2.md); sweep `batch_size` over the precise-probe corner (`data.split=test`,
200/200), one axis at a time:

```bash
for bs in 32 64; do for s in 0 1 2 3 4; do
  card=$(( s % 2 ))
  ./scripts/run_gaudi_dev.sh -m /mnt/stl10 gaudi-env-cafl4ds:latest "$card" \
      python scripts/positive_control_forgetting.py device=hpu \
      hydra.run.dir="outputs/p032c_bs${bs}_seed${s}" seed="$s" data.split=test \
      support_per_class=200 query_per_class=200 \
      'task_a_classes=[0,2,8,9]' 'task_b_classes=[1,3,5,6]' \
      encoder.embed_dim=256 encoder.depth=8 encoder.num_heads=8 img_size=64 \
      ssl.decoder_dim=128 ssl.decoder_depth=4 ssl.decoder_heads=4 \
      epochs_a=300 epochs_b=300 batch_size="$bs" probe=linear recon_masks=16
done; done
```

The read is per-batch PC `BackwardTransfer` (min across seeds vs −0.05) and R11 (task-B accuracy after phase B) against
the batch-128 baseline; a batch that induced forgetting would lift R11 and drive PC BWT robustly negative.
