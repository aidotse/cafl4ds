# Positive control — multi-seed robustness of the forgetting fire (P0.3.2)

[P0.3.0](P0.3.0.md) delivered a passing two-sided forgetting gate and [P0.3.1](P0.3.1.md) mapped the operating point and
showed the ~−0.07 crater is a *task/scale ceiling*, not an under-tuned regime. Both left one caveat sharp enough to
matter: the fire sits near the gate's own −0.05 threshold, and two identical-regime P0.3.0 runs already spanned −0.050 …
−0.071. A metric whose fire brushes its threshold is only trustworthy if that fire is **seed-stable** — i.e. the
*weakest* replicate still clears the bar. P0.3.2 is the collapse-mode P0.2.2 analogue: a multi-seed sweep of the P0.3.0
baseline corner that reports the fire as a distribution and gates on the min across seeds, not a single run.

This began as the first of the carryover substudies meant to bring the forgetting mode to parity with the calibrated
collapse mode; its negative result (below) instead redirected the whole cluster toward finding a dataset that hosts a
robust forgetting event ([P0.3.4](P0.3.4.md)), with the false-positive stress (the P0.2.4 analogue) deferred to
[P0.3.5](P0.3.5.md) once a real fire exists to contrast against.

## Methodology

The harness (`scripts/positive_control_forgetting.py`) and the P0.3.0 baseline corner are held fixed; only `seed`
varies. `seed` is the right knob because it drives **both** sources of run-to-run variance in one place: the task split
(`torch.Generator(seed)` picks the per-class support/query/train partition, `_task_split`) *and* the per-arm
initialisation + phase-A training (`torch.manual_seed(seed)`, `_run_arm`). Each seed is therefore an independent
replicate of the whole PC-vs-healthy comparison — a different data partition *and* a different backbone init — so
min-across-seeds is a genuine worst-case, not just an init reshuffle.

- **Corner:** the P0.3.0 baseline — encoder 256/8 (heads 8), MAE decoder 128/4/4, `img_size=64`, 300 epochs/phase,
    `batch_size=128`, linear probe, `recon_masks=16`, vehicles/animals split (task A = `{0,2,8,9}`, task B =
    `{1,3,5,6}`).
- **Seeds:** N = 5 (`seed ∈ {0,1,2,3,4}`), two per HPU card in parallel (card 0 → seeds 0,2,4; card 1 → seeds 1,3).
- **Read:** per seed, the same gate as P0.3.0 (`comparison.json`); across seeds, the **min / median / max** of the PC
    `BackwardTransfer` and `ForgettingMeasure`, and the PC/healthy contrast, plus the full range of the healthy quiet
    side. The seed-stability claim requires the **worst** seed to still fire (PC BWT ≤ −0.05, FM ≥ 0.05) *and* the
    **worst** healthy arm to still hold (|BWT| ≤ 0.03).

### Mechanism levers held fixed here (carried into P0.3.3)

Two step-count effects are *not* varied in this sweep — they change the true forgetting magnitude/mechanism, not the
measurement noise P0.3.2 targets. They motivated the [P0.3.3](P0.3.3.md) batch-size probe (which found neither induces
forgetting — R11 stays ~0.56 regardless):

- **Batch size** (held at 128 ≈ near-full-batch over ~1,500 task images, so phase A sees the whole task in ~12 steps).
    It reaches forgetting through two channels: (a) *step count* — with epochs fixed, a smaller batch means more B-only
    gradient steps, i.e. more respecialization pressure; but P0.3.1's erosion arm already tripled B-steps (300→900
    epochs) with the crater flat (−0.071→−0.067), so the crater is equilibrium/ceiling-bound, not step-limited, and a
    smaller batch would likely deepen it only modestly; (b) *gradient noise / minima sharpness* — near-full-batch finds
    sharper minima (Keskar et al. 2016), so smaller batches inject SGD noise → flatter minima → often better
    generalisation. The interesting follow-on hypothesis is therefore **stability, not depth**: a smaller batch may
    steady phase-A learning across seeds (`task_a_learned` swings 0.025–0.108 in the 60/60 sweep, itself half the reason
    the fire is fragile), rather than enlarge the crater. Details deferred to [P0.3.3](P0.3.3.md).
- **Inter-arm step-count asymmetry** (structural, not a knob). In phase B the PC arm trains B-only (~12 batches/epoch)
    while the healthy arm replays A∪B (~24 batches/epoch) — so the healthy arm takes **2× the gradient steps** in phase
    B, at any batch size. This is inherent to the replay design and is a plausible contributor to the two-directional
    per-seed swing (the healthy arm's task-A accuracy *rising* on some seeds), separate from probe noise.

## Results

Two N=5 sweeps: the pure single-axis multi-seed sweep at the P0.3.0 corner (60/60 probes, train split), and a
probe-sizing diagnostic (200/200 probes) the first one motivated.

### The fire is not seed-stable (60/60, P0.3.0 corner)

| seed | PC learnedA | PC BWT | healthy BWT | fires (≤ −0.05)? | holds (\|·\| ≤ 0.03)? |
| -- | -- | -- | -- | -- | -- |
| 0 | +0.096 | **−0.071** | −0.021 | ✅ | ✅ |
| 1 | +0.092 | −0.017 | +0.004 | ❌ | ✅ |
| 2 | +0.050 | +0.025 | +0.071 | ❌ | ❌ |
| 3 | +0.025 | +0.050 | +0.071 | ❌ | ❌ |
| 4 | +0.108 | −0.017 | +0.054 | ❌ | ❌ |

min / median / max PC BWT = **−0.071 / −0.017 / +0.050** — only **1/5** fire (seed 0, the original P0.3.0 seed), and the
weakest replicate has the *wrong sign*. The healthy quiet side also breaks on 3/5. Both arms swing ±0.05–0.07 in *both*
directions — the signature of probe-read noise dominating a ~0.07 effect (BWT is a difference of two probe reads, each
on only 240 query images = 60 × 4).

### Bigger probes: the variance collapses, and so does the fire (200/200, test split)

STL-10 train is 500/class, so 200/200 probes would starve training to ~3 batches; drawing from the STL-10 **test** split
(800/class) instead keeps ~13 training batches/task (matching the 60/60 budget) so **only probe size changes**.

| seed | PC learnedA | PC BWT | R11 (task B, PC) | healthy BWT |
| -- | -- | -- | -- | -- |
| 0 | +0.036 | +0.024 | 0.554 | +0.078 |
| 1 | +0.104 | −0.001 | 0.573 | +0.010 |
| 2 | +0.088 | +0.026 | 0.562 | +0.063 |
| 3 | +0.099 | +0.026 | 0.573 | +0.015 |
| 4 | +0.075 | +0.026 | 0.562 | +0.044 |

min / median / max PC BWT = **−0.001 / +0.026 / +0.026** — **0/5** fire. The variance *collapsed* (the 60/60 sweep
spanned 0.121; here 0.027) **and** the center sits at **+0.02** — task A stays flat or drifts slightly *up* under B-only
training. `learnedA` is now stable (~+0.09 across seeds): the bigger probe de-noised the phase-A read, so the erodable
delta genuinely exists and reproduces — but there is no crater to erode it.

## Findings

- **The instrument is sound; the vehicle is not.** A larger probe reduces variance exactly as a correctly-behaving
    estimator should, and converges the estimate to **≈0** (no forgetting), not to the −0.05 threshold. The P0.3.0
    −0.071 was a favorable small-probe draw; it survives neither precise measurement nor other seeds.
- **Mechanistic smoking gun: R11 ≈ 0.56.** Task B (animals) barely learns above its ~0.53 four-way floor (+0.02–0.04),
    while task A (vehicles) reaches +0.09. The representation never becomes B-specialized enough to overwrite A —
    exactly [P0.3.0](P0.3.0.md)'s negative-result #2 (MAE learns broadly transferable structure; B-training *helps* A).
    The vehicles/animals split was meant to break that; under precise measurement it doesn't.
- **P0.3.0 and P0.3.1 are re-scoped, not discarded.** Both toy-scale "passes" rested on seed 0; the multi-seed sweep
    shows they were probe-noise artifacts (P0.3.1's single-seed erosion −0.067 included). Their durable contribution is
    **instrument plumbing + the noise-floor characterisation (a 4-way forgetting BWT needs ~200/200-scale probes) + the
    drift demotion** — not a calibrated forgetting gate. Real calibration moves to a dataset that hosts a robust
    forgetting event ([P0.3.4](P0.3.4.md), CIFAR-100).
- **Confound note.** The 200/200 run changed two things vs P0.3.0 (probe size *and* train→test split). But the pure
    single-axis 60/60 sweep independently agrees (1/5 fire, center −0.017), so the conclusion is robust to the split
    change.

## How to run

Same harness/config as P0.3.0; sweep `seed` over the baseline corner (two per card in parallel):

```bash
for s in 0 1 2 3 4; do
  card=$(( s % 2 ))
  ./scripts/run_gaudi_dev.sh -m /mnt/stl10 gaudi-env-cafl4ds:latest "$card" \
      python scripts/positive_control_forgetting.py device=hpu \
      hydra.run.dir="outputs/p032_seed${s}" seed="$s" \
      'task_a_classes=[0,2,8,9]' 'task_b_classes=[1,3,5,6]' \
      encoder.embed_dim=256 encoder.depth=8 encoder.num_heads=8 img_size=64 \
      ssl.decoder_dim=128 ssl.decoder_depth=4 ssl.decoder_heads=4 \
      epochs_a=300 epochs_b=300 batch_size=128 probe=linear recon_masks=16
done
```

The probe-sizing diagnostic is the same sweep with larger probes drawn from the test split (to keep the training
budget): append `data.split=test support_per_class=200 query_per_class=200`. Each run writes `comparison.json` =
`{gate, pc, healthy}`; the seed-stability read is the min PC `BackwardTransfer` / `ForgettingMeasure` against the −0.05
/ 0.05 fire thresholds and the max healthy `|BackwardTransfer|` against the 0.03 quiet threshold.
