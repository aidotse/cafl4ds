# Positive control (representation-health gate) — the over-powered-decoder lever (P0.5.1)

**What this substudy is.** The decoder-capacity companion to [P0.5.0](P0.5.0.md). Same mode (**shortcut / stable-loss
representation degradation**), same two-sided setup, same instrument verdict on trial — the full framing (the
"full-rank-but-useless" precondition, RankMe blind by construction, alignment/uniformity on trial, the "does the P0.2
suite read quality on MAE" deliverable) lives in P0.5.0 and is not repeated here. The one change is the forcing lever:
where P0.5.0 starves the encoder of pressure with a *low mask ratio*, P0.5.1 removes the pressure from the *other* side
— an **over-powered decoder** — because that is the lever built to stress the mode's central crux hardest, and to give
the **cleaner "loss lies."**

## Why this lever — the sharpest full-rank test *and* the honest loss demonstration

Two reasons to want this lever regardless of where P0.5.0 lands (they vary orthogonal knobs → independent evidence):

- **Sharpest full-rank-but-useless test.** A heavy decoder can reconstruct from almost any invertible encoder output, so
    the encoder is free to emit high-entropy, **full-rank** features carrying no task structure — the cleanest way to
    *manufacture* a full-rank-but-useless rep on purpose. If any lever produces a rep RankMe rubber-stamps as healthy
    while the probe craters, it is most likely this one. So a RankMe **null on the shortcut arm here** (probe cratered,
    RankMe quiet) is the mode's strongest single result — it shows the collapse workhorse has a genuine blind spot only
    the quality readers cover. (If instead the heavy decoder drives the rep *low*-rank, that too is informative:
    shortcut degradation and collapse would share a reader.)
- **The cleaner "loss lies" — apples-to-apples.** P0.5.0's mask-ratio lever changes the reconstruction *task*, so its
    cross-arm loss comparison is not apples-to-apples (see P0.5.0's caveat). Here **both arms hold the mask ratio at the
    healthy 0.75** and solve the *same* task; the shortcut arm keeps the loss low because the decoder *compensates* for
    a poor encoder. That is a truer monitor blind spot — same objective, same difficulty, loss reads fine, rep is bad —
    so P0.5.1 carries the *principled* "loss lies" demonstration even though P0.5.0 is the mechanically simpler entry.

## Design — the delta from P0.5.0

Everything is inherited from [P0.5.0](P0.5.0.md): vehicle (MAE, read at the backbone; **from-scratch primary**),
healthy-vs-shortcut two-arm structure with a seed reset between arms, the instrument suite, the four-condition gate, the
scale/headroom escalation, and **multi-seed from the first launch** (verdict by min-across-N). The differences:

- **Lever = decoder capacity (`ssl.decoder_dim` / `ssl.decoder_depth`, default 64/2 → over-powered, e.g. wide/deep).**
    Both arms at mask 0.75; healthy keeps the lightweight decoder, shortcut over-powers it. Orthogonal to P0.5.0's mask
    ratio.
- **Dose-response on decoder size** (dim and/or depth) to locate where the probe craters while the loss stays low.
- **Read RankMe with particular care** — this is the arm most likely to expose the full-rank-but-useless geometry, so
    the shortcut-vs-healthy effective rank is the **headline** number (alongside probe + alignment), not a corroborator.
- **Loss condition is the general form.** An over-powered decoder keeps the *training* loss low by compensating for the
    encoder, so the shortcut loss need not fall *below* healthy — the "loss lies" condition here is the weaker,
    apples-to-apples "does not separate in the alarming direction."

## Results

Runs: same escalated from-scratch MAE / Imagenette / 200 epochs / 5 seeds, both arms at mask 0.75; healthy decoder 64×2,
shortcut over-powered to 512×8 (kNN-primary gate throughout). The healthy arm reproduces P0.5.0's (linear 0.528 / kNN
0.412) — the sanity check that the shared config is identical across levers.

**The gate fails 5/5 — more cleanly than the mask lever.** The probe crater is essentially zero on every seed (two seeds
slightly *negative* — shortcut kNN marginally above healthy), contrast 0.99–1.03×. The over-powered decoder does not
degrade the encoder's probe accuracy at this scale.

| seed | healthy kNN | shortcut kNN | crater (kNN) | RankMe frac | uniformity gap |
| -: | -: | -: | -: | -: | -: |
| 0 | 0.412 | 0.392 | 0.020 | 1.12 | −0.90 |
| 1 | 0.386 | 0.388 | −0.002 | 1.01 | −0.70 |
| 2 | 0.386 | 0.382 | 0.004 | 0.98 | −0.63 |
| 3 | 0.406 | 0.408 | −0.002 | 1.00 | −0.66 |
| 4 | 0.412 | 0.400 | 0.012 | 0.97 | −0.57 |

**The precondition is clean 5/5 — this *is* the full-rank vehicle.** RankMe frac ≈ 1.0 every seed (shortcut rank
equal-to-or-above healthy), exactly as designed: the heavy decoder lets the encoder emit full-rank features. So the
geometry the mode wants (full-rank) is achieved — what did *not* materialise is the "useless" half.

**"Loss lies" — cleanly, apples-to-apples.** Both arms solve the same task (mask 0.75); the shortcut's reconstruction
loss is *lower* (e.g. floor 0.365 vs healthy 0.418) because the decoder compensates, while the probe is unchanged. The
principled monitor blind spot: same objective, loss reads better, representation no better.

**Reader verdict (the deliverable): the P0.2 quality readers do not read quality on MAE.** Uniformity moves a large
amount in the *wrong* direction on every seed (gap −0.57 … −0.90 — the shortcut looks *more* uniform, i.e. healthier)
while the probe is flat, so it is reading the decoder-driven geometry change (rank-spread / capacity), not quality.
Alignment is weakly right-direction but tiny (mean +0.019, range +0.009…+0.033 across seeds — right-signed, far below
any fire bar). RankMe is blind by construction (the precondition). No reader fires: the suite's quality blind spot on
MAE, earned here as *geometry moves while quality does not*.

## Insights

- **This is the sharpest statement of the instrument verdict.** Where the mask lever left uniformity as noise
    (sign-flipping, one spurious fire — [P0.5.0](P0.5.0.md)), the clean decoder vehicle makes it a *consistent*
    mis-signal — the same large, wrong-direction move every seed. That is stronger than a null: the reader is not
    silent, it is confidently wrong, tracking a geometry change quality does not follow.
- **"Full-rank but useless" split into its two halves.** The decoder lever delivered *full-rank* cleanly but not
    *useless* — the encoder stayed useful. At from-scratch toy scale we can manufacture the geometry but not the quality
    collapse. Producing genuine uselessness likely needs a representation with real quality *to lose* — the
    degrade-*from-competent* path ([P0.5.2](P0.5.2.md), the single successor substudy), which carries this forward (with
    the modest-baseline caveat carried in [P0.5.0](P0.5.0.md)).

## How to run

Same harness as [P0.5.0](P0.5.0.md) (`scripts/positive_control_shortcut.py`), lever pointed at the decoder; Gaudi per
`docs/developing.md`:

```bash
# shortcut arm = over-powered decoder; healthy arm = lightweight (same mask ratio 0.75, everything else equal).
./scripts/run_gaudi_dev.sh -m /mnt gaudi-env-cafl4ds:latest 0 \
    python scripts/positive_control_shortcut.py device=hpu \
    encoder.embed_dim=192 encoder.depth=8 encoder.num_heads=6 img_size=96 epochs=200 \
    'shortcut.mask_ratio=0.75' 'shortcut.decoder_dim=512' 'shortcut.decoder_depth=8' seed=0
    # data=imagenette, ssl=mae, and the healthy 64×2 decoder are config defaults; this is the config run above
```

Multi-seed decoder-size dose-response, then N-seed at the operating point. Read: shortcut-arm probe vs healthy,
**RankMe** first (does it stay quiet on a cratered rep?), then alignment/uniformity, then the recon-loss non-separation.
