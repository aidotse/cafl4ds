# Positive control 4 — redundancy-/dimensional-collapse vehicle (P0.2.3)

The fifth Phase-0 sub-study (P0.2.3; see the [Phase 0 overview](index.md)). It closes the one side of the collapse-suite
calibration that [P0.2.2](P0.2.2.md) could not reach: the **fire** side of off-diagonal covariance (`offdiag_cov`). P0.2
→ P0.2.1 → P0.2.2 calibrated the joint-embedding collapse suite against **point** collapse (SimSiam's
`anti_collapse=False` toggle); P0.2.3 introduces a *second* collapse vehicle whose trivial optimum is **redundancy /
dimensional** collapse — the sub-mode `offdiag_cov` is actually built to catch.

## Why this exists (what P0.2.2 left open)

`offdiag_cov` is confirmed **null everywhere** across P0.2.2's E1/E2/E3 — but that is a *quiet-side* result only. It has
never been shown to **fire when it should**, because the SimSiam `anti_collapse=False` vehicle produces **point**
collapse (all per-dimension variance → 0 ⇒ covariance → 0), not the **redundancy/dimensional** collapse `offdiag_cov`
targets. So `offdiag_cov` currently ships **calibrated on one side only**: we know it does not false-alarm, but we do
*not* know it detects anything. Phase-1 correlated streams are a plausible dimensional-collapse trigger, so leaving this
open is exactly the kind of uncertainty that is cheap to close now and expensive to discover later.

## Scope — a second collapse sub-mode and its vehicle

The failure mode changes: from **point** collapse (every input → one constant vector) to **redundancy/dimensional**
collapse (embeddings keep per-dimension variance but the dimensions become linearly dependent — the representation
occupies a lower-dimensional subspace). The instrument set is unchanged (the same joint-embedding geometry suite read at
**both** surfaces, backbone + projector), so the readings stay directly comparable to P0.2.2. The point of the study is
the *contrast* between how the suite responds to the two sub-modes.

Predictions for the new vehicle (to be confirmed or refuted, mirroring P0.2.2's theory-first table):

| Instrument | Behaviour under redundancy collapse | Prediction |
| -- | -- | -- |
| **Off-diag covariance** | ↑ (dimensions become correlated; off-diagonal magnitude climbs) | **Fires** — this is the sub-mode the instrument was designed for; the headline test. |
| **Per-dim variance** | ≈ healthy (per-dimension variance is *preserved*, unlike point collapse) | **Stays quiet** — the direct discriminator between the two sub-modes. |
| **RankMe / effective rank** | ↓ (the representation is genuinely low-rank) | **Fires** — rank-based detectors see dimensional collapse too. |
| **Uniformity / alignment** | weaker signal (surface clumping is milder than under point collapse) | **Uncertain** — a genuine calibration outcome either way. |

If the point-collapse instruments (variance, uniformity) behave *differently* here than they did under SimSiam, that is
a second, independent collapse sub-mode substantiating P0.2.2's "no strict proxy / complementary-coverage" claim with a
fresh data point.

## Methodology — the vehicle and the fire/quiet criterion

Introduce a second collapse vehicle whose *known-a-priori* trivial optimum is redundancy collapse — a decorrelation
method with its whitening/decorrelation term switched off (a one-toggle ablation *in its own method*, mirroring how
`anti_collapse` toggles SimSiam):

- **Barlow Twins** with the redundancy-reduction (off-diagonal cross-correlation) term removed, **or**
- **VICReg** with the covariance coefficient set to 0 (Bardes et al. 2022 ablate exactly this).

Prefer whichever is the least-invasive add to the SSL factory. The verdict is the same **two-sided** test as P0.2.2's
E1, at the same bars (ratio ≥ 2.0 for down-/up-ratio metrics, gap ≥ 0.5 for gap metrics, **min-across-seeds**, ≥ 4
seeds), on **L2-normalized** embeddings: the decorrelation-term-off arm must separate from the intact arm *and* the
intact arm must stay quiet.

## Implementation additions (code)

Neither Barlow Twins nor VICReg is in the repo yet, so this is a **new `[STD]` method** add:

1. **New `SSLMethod` subclass** — see `cafl4ds/ssl/base.py` and `cafl4ds/ssl/simsiam.py` as the template. It must expose
    the same `embedding_surfaces(x) -> {"backbone", "projector"}` accessor so the existing monitor + envelope pipeline
    works unchanged, and a one-toggle ablation flag that removes the decorrelation term (the redundancy-collapse
    switch, mirroring SimSiam's `anti_collapse`).
1. **Config** under `cafl4ds/configs/ssl/`, with the ablation toggle exposed for the PC arm.
1. **`build_*` in the SSL factory**, wired via Hydra `_target_` like the existing methods.
1. **Unit tests** mirroring `tests/unit/test_monitor.py`'s two-surface / alignment coverage, so the new method is
    exercised through the same monitor path as SimSiam.

## Acceptance criterion

On this new vehicle, `offdiag_cov` **fires** (clears ratio ≥ 2.0, min-across-seeds) under the decorrelation-term-off arm
while staying **quiet** on the intact arm — the two-sided verdict, same bar as P0.2.2's E1. Bonus check: confirm the
*point-collapse* instruments (variance, uniformity) behave differently here than they did under SimSiam, which would
further substantiate the "no strict proxy / complementary-coverage" claim with a second, independent collapse sub-mode.

If `offdiag_cov` *still* does not fire even on a purpose-built redundancy-collapse vehicle, that is itself a reportable
calibration result (the instrument is inert at this toy scale) — document it rather than engineer the collapse harder.

## Findings

Across 4 seeds at the 40-epoch IID STL-10 reference corner, the whitening-off arm produces the predicted
redundancy-collapse fingerprint and the intact arm stays healthy. Read on the **projector** surface (min-across-seeds,
bars: ratio ≥ 2.0, gap ≥ 0.5):

| Instrument (projector) | Healthy | PC (whitening off) | Separation (min across seeds) | Prediction → outcome |
| -- | -- | -- | -- | -- |
| **off-diag covariance** | ~0.0004 | ~0.007 | **13.4× (PC/healthy)** | Fires → **confirmed** — the fire side is closed |
| **per-dim variance** | ~0.0077 | ~0.0075 | **≤ 1.12× (healthy/PC)** | Stays quiet → **confirmed** — the discriminator holds |
| **RankMe** | ~37–42 | ~1.5–2.3 | **17.0× (healthy/PC)** | Fires → **confirmed** |
| **uniformity** | ~−3.2 | ~−0.7 | **2.40 gap (PC−healthy)** | Uncertain → **resolved: fires** |

All four seeds pass the two-sided verdict, so the min-across-seeds separations above are the robust readings. The
off-diagonal-covariance **fire** is the headline: the instrument that was a principled *null* under SimSiam point
collapse (P0.2.2) separates ~13–20× on a purpose-built redundancy vehicle, so it is now calibrated on **both** sides.

**The fingerprint is surface-specific**, and this is the sharpest insight. At the **projector** surface — where the
terminal `BatchNorm(affine=False)` pins every feature to unit variance — the signature is the textbook dimensional
collapse the instrument targets: off-diagonal covariance climbs while per-dimension variance is *flat* (≤ 1.12×). At the
**backbone** surface (no BN pin) the redundancy instead manifests as a **variance drop** (`mean_feature_var` separates
2.8–4.6×) and a rank drop (RankMe ~2.3–2.7×), while `offdiag_cov` there stays **quiet** (≤ 0.22×). So `offdiag_cov`'s
fire is specifically a projector-surface phenomenon — a concrete argument for reading the collapse suite at *both*
surfaces, and the reason the redundancy gate reads the projector surface.

This is a second, independent collapse sub-mode whose instrument response differs from SimSiam point collapse (variance
preserved at the projector rather than cratering everywhere), substantiating P0.2.2's "no strict proxy /
complementary-coverage" claim with a fresh data point.

## How to run

The vehicle is `ssl=barlow` (`cafl4ds/configs/ssl/barlow.yaml`, factory `build_barlow`); its `anti_collapse` toggle is
the redundancy-reduction term, so the existing two-arm harness drives it unchanged — `anti_collapse=True` is the healthy
arm, `False` the redundancy-collapse PC. The pass criterion is the **`gate=redundancy_collapse`** config group
(`cafl4ds/configs/gate/redundancy_collapse.yaml`): it reads the collapse-suite envelope at the projector surface and
requires `offdiag_cov` to **fire** (PC/healthy ≥ 2.0), `mean_feature_var` to **stay quiet** (the discriminator vs point
collapse — its healthy/PC separation stays *below* the fire bar), and RankMe to corroborate. The run recipe mirrors
P0.2.2's E1 two-sided matrix at the 40-epoch IID reference corner, seeds 0–3, probes off (`~ssl.pred_hidden` drops the
SimSiam-only predictor-widening override, which does not apply to Barlow):

```bash
for seed in 0 1 2 3; do
  uv run python scripts/positive_control.py ssl=barlow gate=redundancy_collapse '~ssl.pred_hidden' \
    epochs=40 seed=$seed monitor.run_knn=false monitor.run_linear=false
done
```

**Readout.** The `redundancy_collapse` gate replaces the P0.2.1 point-collapse criterion (a RankMe drop plus a loss
floor riding to the −1 constant-solution value), which does **not** describe redundancy collapse — the projector
BatchNorm holds per-feature variance at unit and the Barlow loss floor is not −1. The gate verdict is written to
`comparison.json` alongside the full method-agnostic **collapse-suite envelope** (separation + fire/quiet per instrument
× surface), which remains the calibration map behind the gate's headline `offdiag_cov` reading. The two-sided
`offdiag_cov` verdict — fires under the whitening-off arm, quiet on the intact arm — is the P0.2.3 acceptance criterion,
read on the projector surface where Barlow's cross-correlation loss operates.
