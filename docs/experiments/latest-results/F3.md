## F3

From the [from-scratch federated MAE sub-study](../federated/F3.md) — the step back from F2: before asking whether
non-IID data hurts, does federated MAE on CIFAR-100 learn at all? Scored on the official test split, before and after
training, with probes fitted on the full training split.

**Learning happens, but only with enough passes.** Centralized MAE learns well from scratch over many epochs, so the
dataset is big enough. A single pass is not: MAE first reorganizes the random features, which briefly makes them worse,
and one pass ends roughly where it started. Federated training makes less progress per pass than centralized, so a
single federated pass ends *below* the random start. Letting each client stream its shard several times (the new
`client_epochs` option) gets past that dip, and federated MAE then learns steadily.

**The non-IID setting is not strong enough to matter.** Dirichlet label skew over 100 classes produced no visible
penalty and almost no extra client drift. A label-free objective sees label skew only through the images each client
gets, and those stay broadly similar.

**Plain FedAvg beats the alternatives.** FedProx and FedAdam exist to correct client drift, and with little drift to
correct they only cost progress. FedProx slows the clients; FedAdam's server step was mismatched at every learning rate
tried, collapsing the model at the default and stalling it at lower values. The label-free health monitors caught the
collapse immediately.

Pretraining on the same CIFAR-100 images again left nothing to learn, as in F2. All results are a single seed, and the
centralized reference at equal passes is still missing. The natural next step is a non-IID setting with real drift, such
as BDD100K split by driving condition.
