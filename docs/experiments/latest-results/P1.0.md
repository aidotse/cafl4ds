# P1.0 — the open-loop harness

Study-level summary of the P1.0 engineering group (build the loop): [P1.0.0](P1.0.0.md) the loop-integration harness,
[P1.0.1](P1.0.1.md) the arm-alignment certificate, [P1.0.2](P1.0.2.md) the deployment-prototype de-risker. Detail lives
in the substudy distillates linked here and, one level down, in [`phase1/P1.0.{0,1,2}.md`](../phase1/index.md).

## The value proposition

Phase 1 has to show that the coupled streaming loop actually degrades on real data. But you cannot *read* degradation
until you have the loop itself — a rig that streams data through a selection filter into a self-supervised backbone and
watches a health monitor, with two reference arms co-logged beside the live one so any movement is read *against a
baseline* rather than in isolation. Those references are a **PC** (a deliberately manufactured pathology, which proves
the instruments can fire) and a **B5** floor (a frozen, never-updated twin). P1.0 builds that rig. It is pure
engineering: it reads *no* degradation, and every degradation read is left to subsequent studies.

The group is three substudies, each closing one gap between "we have Phase-0 pieces" and "we can run open-loop
experiments on real data":

- **P1.0.0** consolidates Phase 0's scattered pieces — the adapting backbone, a separate positive-control script per
    failure mode, the frozen floor measured only at run-end — into **one** multi-arm harness that co-logs the live / PC
    / B5 arms into a single canonical `comparison.json`, proven on the toy STL-10 substrate.
- **P1.0.1** certifies the cheap trick every arm comparison rests on: re-seeding each arm so it "rebuilds the same
    stream," then aligning the arms post-hoc. That assumption was inherited untested from every Phase-0 positive
    control; this substudy measures it against a shared-iterator oracle and owns the resulting number.
- **P1.0.2** takes the certified loop onto the real substrate the exit gate stands on — **BDD100K** — as a
    from-scratch-runnable deployment prototype: a configurable driving diet, a config-selected backbone, and a
    trust-annotated multivariate health corpus anyone can mine without the code.

Why this matters for the project: nothing downstream in Phase 1 runs without a working loop, and — the load-bearing
point — a *null* on BDD is only interpretable as "no coupling" rather than "under-powered / mis-wired" once the
ingestion, the diet, and the logging have first been proven to run and read sensibly. P1.0 is that proof.

## Results

This is an engineering study, so the "results" are what was built and how it was validated — no degradation numbers are
claimed anywhere.

- **P1.0.0 — built; the toy smoke is green.** The harness runs the three arms into one canonical artifact on a shared
    step index. The full 2×2 C×I STL-10 smoke passes in every corner: the rig runs end to end, the live arm reproduces
    P0.1.0 cell-for-cell (so the harness adds PC and B5 *beside* the loop without perturbing it), the collapse PC fires
    identically as a fixed control, the B5 floor stays genuinely frozen, and nothing goes non-finite — plus a
    long-horizon resampled-image run that stays finite with flat (plateauing) memory.
- **P1.0.1 — complete; the same-seed alignment is certified, exactly.** A same-seed rebuild is bit-identical to the
    oracle and the health trajectory does not diverge, because the stream's RNG is isolated from the global RNG and
    Phase 0 re-seeds *per arm*. A deliberate desync control moves every cell, so the zero is a certification, not a
    blind spot. The disposition: sequential same-seed stays the default runner (no fidelity traded, and the arms
    compose); the oracle is retained as a standing re-certification check.
- **P1.0.2 — complete; both validation tiers are green on real BDD100K.** Tier A (the anyone-can-run wiring check)
    passes on the network-free synthetic substrate — no dataset or accelerator, the whole loop runs on a plain CPU in
    seconds; Tier B (sanity-of-readings) passes on the BDD100K val split, driven on a Gaudi2 HPU for throughput — but
    the drive runs on CPU too. Three 5-seed corpora are promoted — warm JE (the primary hand-off), cold JE, and warm MAE
    — each ~277 checkpoints per seed over a **17-leg** day→night walk (BDD val has 18 driving regimes, but the rare
    `dawn/dusk·foggy` one carries no training frames after the held-out reservation, so 17 are streamed). Every corpus
    reads plausibly: finite throughout, RankMe in range, representation drift accumulating across every seed, and the
    labelled scene-canary above chance. The deliverable is corpus-first — the config plus the logged-signal traces, not
    merely a gate verdict.

The apparatus is deliberately number-free: reading any of this movement *as* degradation is P1.1 / P1.3 / P1.4's job.

## The one-line takeaway

The open loop is **built, its arm-alignment certified, and running end-to-end on real BDD100K** with a trust-annotated
health corpus — a number-free engineering foundation the mode studies stand on, with no degradation read anywhere (P1.0
✅ built; every degradation read deferred to P1.1 / P1.3 / P1.4).
