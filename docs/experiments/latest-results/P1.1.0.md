## P1.1.0

From [the healthy-movement null sub-study](phase1/P1.1.0.md) — the first P1.1 piece. Phase 1 asks whether a
self-supervised backbone degrades when it trains on a correlated stream of driving images. The difficulty, known from
Phase 0, is that a perfectly healthy backbone *also* moves its health instruments while it trains. So a reading from the
correlated stream means nothing until we know how much a healthy run moves them. P1.1.0 measures that reference — the
**null** — by driving the same frames twice: once in the correlated order (the **walk**, one driving condition at a
time), and once shuffled (the **IID control**). The two differ only in ordering, so any gap between them comes from
correlation alone.

**Result: from a settled starting model, a healthy drive is quiet; correlation reshapes the joint-embedding backbone
without costing it accuracy, and leaves MAE untouched.**

| Question | Answer |
| -- | -- |
| How much does a healthy drive move the instruments, and does correlation move them further? | From a settled model, barely at all. Correlation then compresses the joint-embedding (JE) backbone's representation and pulls it away from where it started — with no loss of accuracy. On MAE it leaves no meaningful trace. |
| Is the labelled accuracy channel (the canary) strong enough to be ground truth? | Yes. It would have caught a loss of a few points, and the model now sits far enough above chance for a loss to show. It saw none. |
| Does it matter whether the model already saw the stream's frames? | No effect was detected. With one starting model per level, only a large effect is ruled out. |

**Why the starting model mattered.** The first attempt started from a small model trained from scratch, stopped as soon
as its training loss levelled off. That model turned out no better than random weights, and from it even the healthy
drive moved the instruments a lot. That movement was the model still settling, not something a healthy drive does. A
competence study then showed the small model could not learn the task even with labels, while a pretrained one could. So
the final runs start from a pretrained ViT-B, warmed until its accuracy — read on labels kept apart from the canary —
stops moving in *either* direction. Continued training first pulls a pretrained model's accuracy down before it levels
off, and a drive started mid-slide would read that slide as degradation.

**What it hands on.** One phenomenon needs explaining: on JE, correlation compresses the representation and moves it,
while accuracy holds. Its size sits below Phase 0's collapse alarm. Whether it is early collapse that the canary cannot
see, or harmless compression, is P1.1.1's first question; the leg-boundary checkpoints for its recovery tests are saved.
The result does **not** say streaming is harmless in general — the drive is short, about one pass over a few thousand
frames, and damage over a long horizon is P1.3's question.

checkpoints sit temporarily inside the BDD data directory and must be moved once dedicated storage lands. Artifacts are
