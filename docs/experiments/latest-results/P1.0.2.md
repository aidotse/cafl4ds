## P1.0.2

From the [deployment-prototype de-risker sub-study](phase1/P1.0.2.md) — the third P1.0 harness variant. Where P1.0.0
proved the open loop *runs* on toy data and P1.0.1 certified its arm-alignment, P1.0.2 takes the certified loop onto the
**real substrate the exit gate stands on** — BDD100K — as a from-scratch-runnable **deployment prototype**. It streams a
*meaningful, configurable* driving diet (default: correlated `(timeofday, weather)` era blocks walking a day→dusk→night
shift, long-tailed, single-pass) through a **config-selected backbone** (`backbone=mae|je`, run one at a time — the same
seed rebuilds the same regime by P1.0.1's certificate, so no precarious co-step), with **optional** PC/B5 gate arms and
**Phase-0-informed multivariate logging**: the full instrument vector each checkpoint, label-free *and* labelled-canary
channels, every signal tagged with its Phase-0 calibrated status via a code trust-map registry stamped into the
artifact.

**Engineering only — it reads no degradation.** Acceptance is a two-tier validation: an anyone-can-run **wiring check**
(pipeline wired, all channels present, trust map complete, finite, flat memory) and a **sanity-of-readings** pass (the
default diet reads plausibly — RankMe in range, drift accumulates, canary above chance). Both are **codified** in the
report, not eyeballed: Tier B is a `tier_b` block with a `passed` verdict, its floors deliberately loose (aggregates,
not per-checkpoint) so a healthy near-stationary drive does not flap. The diet's scientific adequacy and every
degradation read stay with P1.1 / P1.3 / P1.4.

**The deliverable is corpus-first.** The primary hand-off is the config plus the promoted logged-signal corpus; the
pipeline is the means (it runs other configs). The core is compute-agnostic (one `device` knob spans cpu/cuda/hpu;
`img_size` downscales to fit memory), with hardware confined to the existing Docker / launcher edges — the
anyone-can-run wiring check needs no dataset or accelerator and runs the whole loop on a plain CPU in seconds, and the
full BDD Tier-B drive runs on CPU too, just slower — the accelerator is throughput, not a requirement. The paired
(label-free, canary) traces also set up "predict the canary from the label-free signals" as a *candidate* downstream
multivariate-time-series problem — pending a canary probe-power check (flagged to P1.1): on the default val diet the
canary clears chance by only a thin margin, so whether that mapping is learnable above noise is not yet established. The
harness carries the knobs to strengthen the canary when a study needs it (`query_per_canary`, `min_canary_count`, and
`split=train` for a larger multi-scene probe).

**Status: ✅ complete — both tiers green, on real BDD100K.** The full rig is implemented and validated end-to-end: the
BDD substrate + configurable regime diet, the config-selected backbone (`backbone=mae|je`) with optional gate arms, the
warm-well step (a reusable competent well the drive resumes intact), the seed-ensemble drive with dense checkpointing,
the trust-annotated multivariate corpus (the wide time series + the leg map with its label aggregates + the trust map +
a provenance manifest), and the two-tier validation. **Tier A** — the anyone-can-run wiring check — passes on the
network-free synthetic substrate. **Tier B** — sanity-of-readings on the real default BDD diet — passes on the BDD100K
val split, driven on a Gaudi2 HPU: three promoted 5-seed ensembles (warm JE, cold JE, warm MAE), each ~277
checkpoints/seed over a **17-leg** day→night walk (BDD val has 18 driving regimes, but the rare `dawn/dusk·foggy` one
carries no training frames after the held-out canary reservation, so 17 legs stream), all reading plausibly (everything
finite, RankMe in range, representation drift accumulating across every seed, the labelled scene-canary above chance).
It reads **no degradation**; every degradation read stays with P1.1 / P1.3 / P1.4.

**Post-audit (2026-09-15).** All audit remediations landed in code and docs: the canary held-out reservation is now
decoupled from the drive seed (fixed `canary_seed`, closing the soft transductive leak on warm drives — A1), Tier B is
codified into the report (B1), the source decodes once (A2), `gate_arms` defaults to `false` (B4), and the entry-point
scripts and trust-map/monitor contract gained tests (C1, B2). The three BDD corpora were then **re-driven on the Gaudi2
HPU under the fixed reservation and re-promoted** — 15/15 seeds green on both tiers, the 17-leg walk and the
plausibility verdicts unchanged (the manifest now also records the codified `tier_b_passed`). The canary probe-power
question is carried to P1.1 (C2): on this diet the canary is a thin channel (mean ~0.40–0.41 vs chance 0.33, with
individual checkpoints dipping below chance), which is why its Tier-B floor is an aggregate.
